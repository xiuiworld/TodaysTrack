# 오늘의 트랙 · 브라우저 UI 검토실

실제 Android Views를 바꾸기 전, 사용자와 화면·흐름을 검토하는 로컬 도구다. **웹 구현은 Android 제품 구현 완료가 아니다.** 기준은 `0.3.0-submission(4)`의 `ui/SubmissionScreen.kt`, `SubmissionUiState.kt`, `UiPolicy.kt`와 `MainActivity`의 표시·이벤트다. 출발 소스는 `117f219`이며 시작 시 해당 소스 파일을 읽어 재현했다.

## 실행

`ui-review` 브랜치, `.local/worktrees/ui-review`에서:

```powershell
# 새 체크아웃이라면 먼저 tools/astryx-lab의 lockfile로 의존성을 복원한다.
# npm --prefix tools/astryx-lab ci --ignore-scripts
npm --prefix tools/astryx-lab run build:home
node tools/ui-review/server.mjs
```

브라우저에서 <http://127.0.0.1:4173>을 연다. 기본 포트 변경은 `UI_REVIEW_PORT` 환경변수를 사용한다. 종료는 실행 터미널에서 Ctrl+C. 정적 서버는 Node 내장 모듈을 사용한다. Astryx 수정안은 설치된 별도 lab 패키지에서 한 번 빌드하고, 브라우저 실행 중 외부 네트워크는 사용하지 않는다. 루프백에만 바인딩하며 검토 파일·컴파일된 수정안·기존 장식 표지 3개만 정확한 허용목록으로 제공한다. 저장·업로드 API는 없다. 자동 기동·감시·훅은 등록하지 않는다.

## 검토 방법

- 왼쪽에서 기록 없음·수집 중·생성 대기·접수 불명·저장 완료·오류를 선택한다. 상태 선택은 **예시 세션만 재설정**한다.
- 화면 안의 홈·기록·보관함, 새 기록 설정→시작→마무리→음악 만들기를 눌러본다. 생성 대기와 접수 불명은 앱 영역 바깥에 나타나는 `저장 완료로 진행 (모의)`로 결과를 선택한다. 자동 진행·재송신은 없다.
- 출처 선택은 대역/새 AI 음악 **문구만 모의**한다. 둘 다 가상 곡이며 재생 소리는 없다. 실제 날짜·거리·음원·Room·고정 입력·작업 ID는 읽거나 변경하지 않는다. 모든 mock ID는 REVIEW 접두부를 쓴다.
- 배치·크기·간격·색조는 초안이다. `적용`을 눌러야 현재안이 바뀌며 이전 적용안이 비교 메뉴에 남는다. 같은 상태를 두 안에 함께 표시하므로 사용 흐름에 따른 차이를 비교할 수 있다. 브라우저 localStorage에는 최근 20개 디자인 설정만 저장한다. 기록·곡은 저장하지 않는다.
- 대화로 준비하는 토큰/배치 수정안은 `candidate.json`의 revision·label·config를 갱신한다. 사용자가 `적용`을 누르면 파일을 새로 읽는다. 미적용 수동 조정과 새 파일 수정안이 함께 있으면 수동 조정을 먼저 보존·적용하고 다음 클릭에서 새 파일을 반영한다. 자동 새로고침·폴링은 없다.
- `기준값 불러오기`도 적용 전까지 현재안을 바꾸지 않는다. 비교 메뉴는 0.3 기준안 및 이전 적용안을 제공한다. 현재 비교 기능은 **설정값·분할/상세 집중 배치의 이력 비교**다. 향후 마크업·렌더러 자체를 바꾸는 피드백은 별도 버전 렌더러/정적 스냅샷을 먼저 보존해야 한다. 기존 이력을 새 코드로 재해석해 완전한 이전 화면 보존이라고 주장하지 않는다.
- CarUx 확인 전/제한은 시작·선택·설정·생성·재생을 비활성화한다. 현재 Kotlin UiPolicy대로 수집 마무리와 일시정지는 유지한다. 앱 탐색·상세 열기의 기존 동작도 유지한다.

## 차이와 경계

현재 화면 구조·문구·이벤트를 CSS/JavaScript로 옮긴 **기능적 재현**이며 픽셀 일치를 보장하지 않는다. 앱 내부 터치 프레임은 최소 76×76 CSS 검토 단위, 보이는 버튼은 별도 크기로 구성한다. 맞춤 축소율을 표시한다. CSS px·브라우저 글꼴·스크롤·dialog는 Android dp·글꼴·AlertDialog와 다르다. 좁은 창(960 미만)에서는 기록 선택창을 사용한다. 상세 집중 배치는 검토용 선택지다.

SDK 수집·백그라운드·실제 CarUx 이벤트·Room·인증·요약·네트워크·음악 생성·다운로드·Media3·오디오 포커스·차량 접근성은 실행하거나 검증하지 않는다. 모의 저장 완료는 실제 저장 증거가 아니다. 일반적인 앱·Pleos 에뮬레이터·음악 서버를 기동하지 않는다. 실제 Android Views 반영은 사용자 방향 확인 뒤 진행한다. 핵심 로직/API 계약 변경이 필요하면 제안을 먼저 알린다.

추가 유료 호출·영상/제출 패키지·외부 업로드/배포·push·Guard·훅·상주 작업자·개인 메모리 저장은 수행하지 않는다. 기획서 두 개·설계 v0.2·7번 공란·후속 계획과 Windroid 중단을 유지한다.

## app-020 · 현재 검토안

흰 배경과 검정 강조, 새 t/트랙 벡터 로고를 적용했다. 홈은 새 기록/저장 음악의 두 진입점으로 바꿨고, 기록 목록→상세→관측·작업 정보, 보관함 재생, 새 기록 설정을 같은 앱 영역 안에 연결했다. src/review의 화면별 React 모듈을 사용하며 단일 index.html 문구만 바꾼 시안이 아니다. 실제 Android 구현은 그대로다.

기본 창은 보존된 320dpi 관측 bounds [853,152,2535,1362]에서 확인한 841×605dp, 다른 기준은 160dpi bounds [853,90,2535,1300]의 1682×1210dp다. 시스템/차량 패널을 제외한 앱 영역만 그린다. 브라우저에 맞춰 전체 앱을 축소해 표시하므로 실제 기기 dp 실측과는 다르다. 현재 기기를 새로 켜서 측정하지 않았다.

하단 홈/기록/보관함으로 이동한다. 상단 기존 안 비교는 같은 모의 상태를 기준안과 함께 보여준다. 검토 도구를 열면 상태·차량 제한·강조색·글자/간격을 선택하고 적용으로 반영한다. 설정은 새 기록에만 적용하며, 접수 불명은 원래 작업 확인만 모의한다. 기록 마감 상태도 별도 선택할 수 있다.

versions/white-v03에는 Astryx 도입 전 원본 HTML/JS/CSS/fixture와 SHA256 manifest를 보존했다. 첫 두 홈 수정안도 home-review-v1.tsx / home-review-v2.tsx로 고정하고 각각 별도 번들로 빌드한다. renderer 이름은 original / astryx-home-v1 / astryx-home-v2 / astryx-app-v3다. 향후 구조를 바꿀 때는 현재 렌더러 소스·빌드를 새 버전과 분리해 보존한다.

### 기록과 음악 연결 (app-010)

기록 목록에 연결된 음악을 표시하고, 상세는 화살표 뒤로가기/기록 정보/이 기록의 음악으로 정리했다. 저장된 곡은 표지·곡명·장르/가사·길이·출처와 재생을 함께 보여준다. 미생성/수집 중/대기/접수 불명/오류는 음악 영역 안에서 구분하며, 새로운 만들기는 생성 전 기록에서만 제공한다. 보관함의 곡 본문을 누르면 원래 기록 상세로 돌아간다. 노래 이름·ID·원래 기록 연결을 재생성하거나 변경하지 않는다.

상단 기존 안 비교는 이번 수정 전(app-006/astryx-app-v4)을 기본으로 연다. src/review-v4의 표시 마크업과 번들을 보존했으며 상세를 나란히 비교하도록 화면 경로 공유 어댑터만 연결했다. 두 프레임은 같은 기록 상세/목록 경로를 공유한다. 0.3 기준안 및 app-004도 검토 도구의 비교 선택에서 유지한다. Apply는 현재 가상 기록과 상세 경로를 보존한다.

이번 검증은 841×605/1682×1210의 기록 목록·상세·보관함 40개 상태 관측과 실제 클릭 흐름이다. `.local/ui-home-evidence/car-layout/records-library-checks.json`에 범위와 결과를 기록했다. 네이티브 구현 또는 실제 소리 재생 검증은 아니다.

큰 글자/표지 조절값에서도 목록 행 높이를 내용에 맞춘다. 자동 포커스는 제목을 읽게 하되 입력창 같은 테두리를 만들지 않는다. 실제 버튼/입력의 키보드 포커스 표시는 유지한다.


### 제목/시각 분리와 보관함 음악 상세 (app-012)

기록 제목 아래 시각을 빼고, 기록 시각과 연속 관측 거리를 별도 행으로 나눴다. 반복되는 설정 설명은 음악 영역에만 둔다. 보관함의 곡 본문은 독립 음악 상세로 열리며 보관함 탭을 유지한다. 음악 상세의 원래 기록 보기로만 기록 상세를 연결하고, 브라우저 뒤로가기는 같은 음악 상세로 돌아온다. 제한 상태에서 이력 복원으로 다른 기록/곡을 여는 우회도 막는다.

i 안내는 사용 흐름/데이터 안내로 바꾸고, 기록 정보에는 음악 상태와 거리 의미를 표시했다. 요청 ID/작업 ID/고정 입력은 접어두며 원문을 보존한다. 상단은 i→설정 순서의 공통 테두리로 묶고, 보이는 아이콘 중심 간격만 60/90 검토 단위로 좁혔다. 각 터치 프레임은 76/114를 유지한다.

이번 수정 전(app-010/astryx-app-v5)은 src/review-v5와 /home-review/v5에 보존했다. 상단 비교 버튼의 기본 대상이다. 이전 안에 음악 상세가 없으므로 새 음악 상세를 비교할 때 이전 보관함 목록이라는 문구를 명시한다. Android와 실제 음악 생성/재생은 변경하거나 실행하지 않는다. .local/ui-home-evidence/car-layout/detail-content-checks.json에 두 크기 26개 관측과 경로 검증을 기록했다.


### 큰 커버·독립 재생 영역·새 팝업 (app-013)

음악 상세의 기본 커버는 240/360 검토 단위로 직전 120/180보다 커졌다. 재생 제어는 커버/곡 정보 아래 별도 영역에 둔다. 재생/일시정지 외 동작을 약속하는 가짜 탐색/이전곡 버튼이나 진행 타이머는 추가하지 않았다.

기본 화면은 제품 모양으로 검토한다. 대역/실제 생성 없음 등의 긴 검증 문구는 앱 내부에서 숨기고, 앱 바깥의 상시 검토 데이터·출처 모의·실행 없음 안내로 분리했다. 검증 표시를 켜면 내부 출처 설명과 요청/작업/고정 입력을 볼 수 있다. 실제 출처 값이나 ID는 변경하지 않으며 Android의 출처 표시를 제거한 작업이 아니다. 날짜/거리/곡은 계속 가상 데이터다.

설정/이용 안내/기록 정보/음악 만들기는 공통 제목/닫기/스크롤 본문/하단 액션으로 통일했다. 설정은 드롭다운 대신 큰 선택 버튼을 사용하며 취소는 버리고 저장은 다음 새 기록에만 반영한다. 기록 정보는 행으로 정리하고 기술 식별자는 검증 표시에서만 펼친다. 음악 만들기의 요약 전송 안내와 CarUx 차단은 유지한다.

수정 전 app-012는 src/review-v6, /home-review/v6에 보존했다. 상단 비교의 기본 대상이다. 최신 근거는 .local/ui-home-evidence/car-layout/player-panels-checks.json의 30개 배치 관측과 실제 클릭 기록이다. 큰 커버 수치는 실제 img 요소에서 따로 측정했으며 0 크기 레이아웃 보조 노드를 커버로 세지 않았다.


### 아이콘과 공유 재생 위치 (app-014)

홈과 음악 상세는 같은 재생/일시정지 아이콘 및 0:00—1:30 위치 바를 사용한다. 기록 상세/보관함 행도 아이콘 버튼을 공유한다. 기록의 일시정지 글자 줄바꿈을 제거했고 음악 상세의 재생 대기 문구는 없앴다. 원래 기록 연결은 음악 상세 상단 오른쪽 기록 보기로 고정했다.

위치 바는 브라우저 검토용 타이머다. 소리/실제 미디어/서버는 연결하지 않는다. 부모 검토 문서가 보이고 재생 중일 때만 시간을 진행하고, 일시정지/곡 끝/숨김/문서 종료 시 타이머를 멈춘다. 화면 이동/적용/비교는 같은 위치를 공유하며 일시정지 위치에서 이어진다. 바를 누르거나 키보드로 이동할 수 있고, 다른 곡의 바를 선택하면 기존 모의를 멈추고 그 곡의 위치를 선택한다. 제한/확인 전에는 새 재생과 위치 변경을 막고 일시정지는 유지한다.
