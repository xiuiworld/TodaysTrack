# Today's Track — optional Guard run contract

기본 실행은 inline과 S 묶음 단위 자체 검토다. 이 문서는 명시적으로 선택한 Guard run에만 적용한다. S1~S4는 11월 15일 제출 묶음, P0~P8은 후속 상세 기술 분류다. 전체 목표 맥락은 실행 승인이 아니다.

## 권한과 범위

- 실제 사용자 실행 지시 원문·승인 묶음/기술 범위·파일·고정 검사를 대조한다. 설정 요청·예시·SELF_TEST를 승인으로 쓰지 않는다. 문자열 검사기는 사용자 원문 출처/의미를 인증하지 못한다.
- approvedStages와 scope.units는 일치한다. 승인된 범위를 매번 재질문하지 않으며 미승인 선행/다음 묶음·후속 P를 추가하지 않는다. S의 구현 결과로 관련 P 항목 일부를 확인할 수 있어도 P 전체 완료가 되지는 않는다.
- partial은 해당 부분 결과만 뜻한다. full도 실제 완료 조건/선행 증거가 필요하다. S full은 제출 범위에 한정된다. 후속 상세 체크리스트를 전부 제출 장벽으로 만들거나, 반대로 미충족 제품 요구를 삭제하지 않는다.
- 외부 선행 증거는 해시뿐 아니라 코드/환경 적용성을 reviewer가 확인한다. 미지원 실험은 실험 수행 완료일 수 있으나 기능 지원을 뜻하지 않는다. 미확정 의존성을 남기고 승인된 독립 작업은 계속한다.
- deviceExecution은 승인 단위의 기기 검사만 허용한다. 유료 API는 별도 원문·음악/가사별 호출 상한·총액/통화가 필요하다. 설정/단계 승인으로 충전·유료 전송을 하지 않는다. 키/토큰은 채팅·spec·로그에 넣지 않는다.
- S2는 외부 AI 전송 없는 대역 연결이다. S3 live는 대역 저장/재감상 확인과 별도 유료 승인 뒤에만 수행한다. S4는 로컬 영상/패키지 준비이며 제품 수정·공개/업로드·이메일·배포 권한이 아니다.

## 작업과 검사

- 한 구현 lane과 controller 독립 reviewer만 쓴다. 추가 자동 분업·상주 에이전트·훅·메모리를 만들거나 전역 Guard/Windroid를 변경하지 않는다.
- task.paths만 편집하고 context/guard 파일은 읽기 전용으로 둔다. 기획서 두 개와 설계 v0.2는 현재 변경 범위가 아니다. 제출용 7번은 공란 유지다.
- 원문 공통 제약과 해당 묶음 완료 조건을 worker/reviewer 모두에게 제공한다. 기존 probe는 완성 제품이 아니다. 합성/실차·대역/실제 AI·파일 검사/청취·SDK 관측/공백을 구분한다.
- check는 자기 묶음 requirement에만 연결한다. 후속 검사를 앞 묶음에 섞지 않는다. local/device/paid-api 분류와 caller 권한을 정직하게 적용한다. pending ticket을 기존 권한 정책으로 수행하고 continue하며 거절을 우회하지 않는다.
- 숫자 비용 한도/사후 쓰기 검사는 실제 서버 과금 통제나 OS 보안 경계가 아니다. 승인 잔여량·durable attempt·불명 시 재송신 금지·서버 dispatch 차단을 확인한다.
- 동일 실패가 두 번 반복되면 조사/접근 변경/의존성 격리를 한다. 한도나 증거 부족을 요건 완화로 통과시키지 않는다.

## 종료

승인 범위가 끝나면 종료하고 미승인 단계로 자동 이동하지 않는다. 원본 반영은 run이 멈춘 뒤 diff·original-baseline 해시·새 파일 충돌을 확인해 승인 파일만 바깥 에이전트가 수행한다. 자동 copy-back/공개/배포는 없다. 실제 기술 증거/한계를 기록하고 Guard 판정·통합·기능 성공·제출 묶음 완료·전체 제품 완료·접수 완료를 구분한다.

작은 probe는 p0-run-contract.md도 따른다. S1에 포함된 probe 부분 결과만으로 S1 전체 완료를 보고하지 않는다.
