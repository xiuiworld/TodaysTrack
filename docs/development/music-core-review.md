# 음악 핵심 검토 · 입력에서 요청까지

음악 핵심을 실제 Kotlin으로 실행한 로컬 검토 기록이다. 앱·Pleos·음악 서버·사이트를 실행하지 않았고 추가 유료 호출은 0이다. 음원이 생성됐거나 청취 품질이 확인됐다는 뜻은 아니다.

## 큰 흐름

1. 차량은 위치·시각·거리와 실제 수신이 확인된 추가 신호를 원본으로 보관한다. 권한 거절/미지원/공백을 함께 남긴다.
2. 차량 안의 공통 엔진이 유효 관측, 제외 이유, 이동 규모, 위치 반복, 방향/소스 변화와 관측 가능한 순서를 만든다. 서버에는 좌표 없는 특징과 근거 참조만 보낸다.
3. 사용자가 선택한 메모/음성/사진/영상/환경음/흥얼거림은 동의 범위로 분석한다. 발언·센서 사실·출처 있는 맥락·미디어 추정·창작을 구분한다.
4. 여정에서 전개/반복/대비를, 선택 재료에서 주제를, 사용자 취향에서 장르/편성/보컬을 정한다. 같은 입력과 변주 식별자면 같은 구성안/요청이다.
5. 음악 AI가 가사와 곡을 함께 만든다. 별도 AI 가사 초안을 보내지 않는다. 사진은 직접 사용 동의된 파생본만, 영상/음성은 분석 설명으로 전달한다.
6. 승인·요청 수·비용 상한과 내구 attempt를 확보한 뒤만 전송한다. 접수 불명은 보류하고 자동 재송신하지 않는다. 반환 가사·구조·음원과 파일 검사/청취 검증을 나눠 저장한다.

## 대표 입력 한 개

합성 왕복 사례는 위치 관측 `A → B → C → C → B → A`, 유효 누적거리 차분 합계 8km다. 실제 주행/정차/집 방문의 증거가 아니다. 다른 관측값과 응답은 비동기로 취급한다.

새 해석에서는 관측된 위치 구간이 **변화 → 같은 위치 반복 → 다시 변화**의 3부분이다. 이 합성 입력의 관측 범위 비중은 각각 1/3이며 실제 운전 시간이나 음악 재생 시각이 아니다. 같은 위치 반복 부분에서는 레이어를 덜거나 교환하는 대비를, 앞뒤에서는 모티프 변형을 지시한다. 시작/끝의 관측 근접성은 변형된 테마 회상의 창작 근거로 쓸 수 있지만 ‘귀가했다’는 사실로 쓰지 않는다.

같은 입력을 FUNK로 선택하면 베이스/드럼/리듬 응답 중심의 편성을, DREAM_POP으로 선택하면 잔향·공간·질감 중심의 편성을 만든다. 메모가 없으면 창작 주제를 선택하고, “미뤘던 일을 마친 날을 기념하고 싶다”를 허용된 메모로 넣으면 그것이 가사 주제의 근거가 된다. 주행 수치와 GPS 관측 문장을 가사에 치환하지 않는다.

장르를 바꾸지 않아도 위치 반복 비중, 방향 변화, 확인 가능한 소스별 변화의 배치, 관측 구간 비중과 선택 재료가 구성안을 바꾼다. 실제 생성 음원의 차별성·듣기 좋은 정도는 아직 확인하지 않았다.

## 같은 입력의 기존 결과와 새 결과

기존 열은 보존된 `117f219` 비교 report의 결과다. 새 열은 현재 Kotlin 엔진 실행 결과다. 원본 입력은 같다. 기본 표의 0은 해당 거리 차분 합계이며 실제로 0km를 운전했다는 뜻이 아니다. 근거가 없는 0 수치는 새 음악 요청에서 제외한다.

|---|---:|---:|---:|---:|---:|
| 합성 왕복·같은 위치 반복 | 8 | 8 | 0 | 3 | 0 |

| 위치만 공백 | 2 | 2 | 0 | 2 | 0 |
| 누적거리 소스 공백 | 8 | 0 | 8 | 1 | 0 |
| 단조 시각 역행 | 9 | 1 | 0 | 2 | 0 |

## 결함·제품 판단·후속 검증

**수정한 구현 결함:** 공백 거리의 연속 거리 편입과 시각 역행 거리 누적은 앞선 검토의 수정/회귀 증거를 보존했다. 이번 엔진은 FRESH 표시에만 의존하지 않고 오래됨·중복·역순·요청 시각과 알려진 epoch 시작을 재검사한다. 방향각 평균은 원형 평균을 쓴다. 분석 전용 intent의 음악 작업 전환, 무가사 편성의 보컬 지시, JSON 안에 반환된 가사/구조의 혼합도 회귀 검증 후 수정했다.

**제품 판단이 필요한 음악 해석:** 반복 관측에 어느 정도 모티프 반복을 줄지, 방향 변화에 얼마나 대비를 줄지, 시작/끝 근접성을 어떤 테마 회상으로 쓸지는 창작 정책이다. 코드가 이를 감정 측정/확정 방문 사실로 바꾸지 않게 했고, 구성안과 근거를 노출했다. 실제 노래를 승인된 환경에서 들은 뒤 취향·해석을 조정해야 한다. 현재 통과한 테스트가 이 선택의 최종 승인은 아니다.

**다음 실제 통합:** Android 담당자의 필드별 수신·권한·수명 결과와 계약 연결, 실제 계정/기기 등록, 승인된 외부 분석·음악 생성, 반환 가사와 실제 가창 대조·청취, 차량 첫 클릭/폰 재생성/앨범·동기화를 확인해야 한다. 추가 유료 호출/앱·Pleos·음악 서버 실행은 별도 승인 전까지 하지 않는다.

인수 상세와 오류/상태 전이는 `music-core-handoff.md`, 실행/검증 근거는 `music-core-implementation.md`에 있다.
