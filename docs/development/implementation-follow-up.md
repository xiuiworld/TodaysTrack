[제출용 네 묶음](implementation-plan.md)은 전체 제품 범위의 일부를 먼저 시연하는 계획이다. 내부·제출용 기획과 설계 v0.2는 유지한다. 아래 항목은 삭제하거나 완료 처리하지 않는다. ## 후속 순서와 의존성

1. 제출 시 verification 자료에 S별 구현·검증·미검증과 위 P별 미충족 항목을 연결한다. 완료한 코드/환경 증거만 재사용한다.
2. 백그라운드가 미해결이면 P0 지원 경로를 먼저 해결하고 P1의 해당 제품 요구를 닫는다. 독립 저장·요약·서버 작업은 승인 범위에서 진행 가능하다.
3. P6는 P1 이후 해당 하위 시험부터 진행하며 차량 핵심 흐름·폰 전체의 일괄 선행 장벽으로 만들지 않는다. 측정하지 않은 하위 범위는 계속 열어 둔다.
4. 계정/기기·비용/삭제·동기화 계약을 확장한 뒤 폰/앨범을 연결한다. P7의 비과금 대역 작업을 P5 유료 대기 때문에 전부 막지 않는다.
5. 자동화/보관 정책과 운영 적합성을 확인한다. 12월 PT 고도화와 출시/배포는 별개이며 현재 후속 착수나 배포를 승인한 것은 아니다.

S2의 개발 등록 자격과 제한된 동시성은 제출 버전의 가정이다. 이를 일반 사용자 로그인·회전 자격·여러 기기 안전성으로 확대하지 않는다. 복잡한 자동 복구를 미뤄도 접수 불명 자동 재송신 차단·비용 한도·키/원본 보호는 제출 버전부터 유지한다.

## 결정/검증의 상태

- **확정:** 제품 방향·기획 전체·설계 v0.2, 11월 15일 제출 목표, 지금은 계획/설정 수정만.
- **작업 결정:** 제출은 S1~S4 우선, 기본 inline 실행/자체 검토, Guard 선택 사용. 후속 P분류를 현재 제출 의존성으로 자동 추가하지 않음.
- **가정:** 단일 등록 개발 차량/owner·수동 마감·템플릿 가사·동시 생성 비활성으로 시연 경로를 제한할 수 있음. 실제 구현/권한·음원 조건은 실행 시 검증.
- **필요 시 사용자 결정:** S1에서 실제 백그라운드가 안 될 때 화면 유지형 제한 시연 채택 여부, 폰 플랫폼, 보관 성향, 신규 유료 호출의 구체 범위. 현재 미리 인터뷰하지 않음.
- **미검증:** 새 제품 수집/서버/미디어 경로·모든 S 묶음·위 후속 항목. 기존 Activity/Python probe는 이를 대신하지 않음.

실제 증거는 technical-validation.md에 환경·revision·명령·run 경로·해시·한계를 남긴다. 보관본의 체크박스나 Guard 완료 표시만으로 전체 단계/제품 완료를 선언하지 않는다.
