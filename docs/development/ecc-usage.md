# ECC 사용 안내

확인일: 2026년 11월 12일

## 설치된 구성

**Everything Claude Code(ECC) 2.2.3**을 현재 Windows 사용자의 Codex에 전역 설치했습니다. Claude Code CLI는 이 설치에 필요하지 않습니다. 다른 프로젝트를 Codex에서 열어도 같은 사용자 설정을 사용하면 ECC를 사용할 수 있습니다.

| 항목 | 설치·확인 내용 |
| --- | --- |
| 공식 저장소 | `https://github.com/affaan-m/ECC` |
| Codex 등록 이름 | `ecc@ecc` |
| 설치 버전 | `2.2.3` |
| 설치 위치 | `C:\Users\xiui\.codex\plugins\cache\ecc\ecc\2.2.3` |
| 설치 범위 | 현재 사용자 Codex 전역. 프로젝트마다 재설치할 필요 없음 |
| 확인한 상태 | 사용자 환경의 플러그인 목록에서 installed/enabled 확인, 캐시의 manifest 참조 경로와 주요 스킬 파일 확인 |

플러그인 등록과 파일 검증을 완료한 상태입니다. 현재 열린 채팅에서 새 스킬이 실제로 호출되는 것까지 검증한 것은 아닙니다. 다음 턴 또는 새 채팅에서 스킬을 확인하고, 목록에 보이지 않으면 Codex 앱을 재시작하세요.

## ECC는 무엇인가

ECC는 개발 에이전트가 참고하는 작업 절차와 기술별 지침을 모은 플러그인입니다. 별도의 AI 모델이나 음악 생성 엔진은 아닙니다. 현재 프로젝트에서는 Kotlin·Android 구조, 비동기 처리, 테스트, 검증과 코드 점검에 필요한 지침을 선택해서 사용하면 됩니다.

스킬을 모두 읽거나 실행할 필요는 없습니다. 자연어로 필요한 작업을 요청하면 관련 스킬을 선택할 수 있고, 특정 스킬을 이름으로 지정할 수도 있습니다.

## Codex에서 쓰는 방법

Codex 입력창에서 `$`를 입력해 스킬을 찾아 선택하거나, 아래와 같이 이름을 포함해 요청하세요. 다른 플러그인과 비슷한 이름이 있으면 ECC 소속 항목을 선택합니다. CLI·IDE에서는 `/skills`로 목록도 확인할 수 있습니다.

### 사용 가능한 스킬부터 확인

```text
$ecc-guide 오늘의 트랙 프로젝트에서 쓸 만한 ECC 스킬과 역할을 간단히 설명해줘.
```

### 구조 검토

```text
$android-clean-architecture docs/proposal.md를 읽고
Pleos 데이터 수집, 음악 변환, 재생을 어떻게 나눌지 제안해줘.
아직 구현하지 말고 필요한 최소 구조만 설명해줘.
```

### Kotlin 구현·리뷰

```text
$kotlin-patterns 이번에 요청한 기능을 기존 구조에 맞춰 구현해줘.
범위를 늘리지 말고 관련 코드와 오류 처리를 함께 확인해줘.
```

### 위치 이벤트와 비동기 처리

```text
$kotlin-coroutines-flows 위치 업데이트의 수집·취소·오류 처리를 검토해줘.
화면이 종료되거나 기록을 멈췄을 때 구독이 남지 않는지 확인해줘.
```

### 테스트 설계

```text
$kotlin-testing 같은 주행 기록에서 기본 악보가 재현되는지와
기록의 한 특징이 바뀌었을 때 해당 음악 요소가 바뀌는지를 검증해줘.
프로젝트에 맞는 테스트만 사용해줘.
```

### 완료 전 검증

```text
$verification-loop 이번 변경에 필요한 검증을 실행하고,
확인한 것과 아직 검증하지 못한 것을 구분해서 보고해줘.
```

### 개인정보·보안 검토

```text
$security-review 위치 기록, 외부 API 키, 공유 링크와 데이터 삭제 흐름에서
이번 변경이 만드는 위험과 수정할 부분을 검토해줘.
```

이 예시들은 사용법입니다. 설치 작업 중에 제품 개발이나 테스트를 시작한 것은 아닙니다.

## Superpowers와 함께 사용할 때

현재 설치된 Superpowers는 해당 작업의 요구사항·설계·구현·검증 절차를 돕고, ECC는 Kotlin·Android 등 구체적인 기술 지침을 보완하는 방식으로 사용합니다. 같은 작업에서 두 도구의 계획·리뷰 절차를 형식적으로 중복 실행하지 않습니다.

프로젝트의 [AGENTS.md](../../AGENTS.md)에 사용자의 기존 작업 선호와 ECC 적용 우선순위를 기록했습니다. 기본은 한 명의 구현자가 승인된 범위에서 계속 작업하는 방식입니다. ECC 예시의 커버리지 80%, 웹 E2E 도구, 자동 병렬 에이전트 사용을 프로젝트 요건으로 자동 채택하지 않습니다.

다른 프로젝트에서는 해당 프로젝트의 AGENTS.md와 기술 스택을 따릅니다. TodaysTrack의 제품 요구사항은 다른 프로젝트에 적용되지 않습니다.

## Claude 명령어와 Codex 스킬의 차이

인터넷의 ECC 소개에는 Claude Code용 `/plan`, `/tdd`, `/code-review` 같은 명령이 나올 수 있습니다. 이 명령이 Codex에 같은 형태로 추가된다고 가정하면 안 됩니다. Codex에서는 설치된 `$스킬이름` 또는 자연어로 요청하세요. 예를 들어 계획은 “ECC 지침을 참고해서 구현 계획을 작성해줘”, 리뷰는 “현재 변경을 요구사항과 회귀 관점에서 검토해줘”라고 요청하면 됩니다.

## 훅과 추가 도구

네이티브 ECC 플러그인에는 세션 시작 훅과 Chrome DevTools MCP 설정도 포함됩니다. 스킬 사용 자체를 위해 훅을 신뢰하거나 브라우저 도구를 실행할 필요는 없습니다. 이번 작업에서는 훅 신뢰 설정을 승인하거나 세션 훅을 실행하지 않았습니다.

CLI에서 자동 세션 훅을 사용하고 싶을 때는 `/hooks`에서 실제 명령을 검토·승인하는 별도 절차를 따르세요. 훅의 런타임 의존성과 실제 실행은 이번 설치 검증 범위에 포함되지 않습니다. 스킬을 사용하기 위해 훅 신뢰 확인을 우회하지 마세요.

## 설치 확인·업데이트·삭제

일반 사용자 PowerShell에서 실행합니다. Codex가 사용하는 사용자 설정과 다른 샌드박스에서는 플러그인 목록이 다르게 보일 수 있습니다.

설치 확인:

```powershell
codex plugin list --json
```

목록에서 `ecc@ecc`의 `installed: true`, `enabled: true`를 확인합니다.

업데이트:

```powershell
codex plugin marketplace upgrade ecc
codex plugin add ecc@ecc
```

업데이트 후 Codex를 재시작해 새 버전을 확인하세요. 네이티브 플러그인을 사용 중이므로 구형 `sync-ecc-to-codex.sh`나 프로젝트별 스킬 복사를 추가로 실행하지 않습니다.

삭제:

```powershell
codex plugin remove ecc@ecc
```

현재 사용자 전역 설치이므로 삭제하면 다른 프로젝트에서도 ECC가 제거됩니다. TodaysTrack의 기획 문서는 유지됩니다.
