# 음악 생성 핵심 구현 기록

기준: `117f219` / `0.3.0-submission(4)`, 브랜치 `logic-review`, 전용 worktree.

## 승인과 고정 범위

사용자 실행 지시: **“PLEASE IMPLEMENT THIS PLAN: 오늘의 트랙 음악 생성 핵심 구현 계획”**.
최신 책임 보정: **“안드로이드 앱은 로직정도만 잡고 구현은 다른애한테 맡길거야. 너는 음악만드는 핵심로직에 집중해.”**

- Android에 의존하지 않는 Kotlin 입력 계약·특징 추출·구성안·프롬프트와 관련 서버의 미디어·작업·비용·결과 처리를 구현한다.
- 수동 메모·음성·사진·영상·환경음·흥얼거림 포함. 자동 녹음·촬영·주기적 마이크 접근 없음.
- 가사·곡은 음악 AI가 함께 작성. 별도 가사 AI 없음. 미디어 AI는 허용된 재료를 해석하는 역할이다.
- 일반 사용자별 소유권, 차량 최초 생성/폰 기존 성공 범위 재생성, 기기 원본/서버 요약 보관. Android·폰·UI·앨범 구현은 별도 담당이다.
- **추가 유료 호출 0, 앱·Pleos·음악 서버 실행 금지.** 로컬 JVM/파일/DB 테스트·대역만 실행한다. 실제 기기·외부 AI·가창/청취 성공으로 확대하지 않는다.
- 기존 SDK 원본·frozen 입력·작업·음원·비용 원장, 기획서 두 개·설계 v0.2·후속 계획·7번 공란 보존.
- main·Android 앱·UI/테마/자산 수정 없음. 기존 검토에서 이미 변경한 차량 순수 요약기 2파일은 보존하며 이번에 추가 수정하지 않는다.
- 자동 push·배포·업로드·영상/패키지·Guard·훅·상주 에이전트·추가 에이전트·개인 메모리 저장 없음. Windroid 중단 유지.
- 기본 한 명 inline, 묶음별 자체 검토. 같은 실패가 두 번 반복되면 원인 조사/접근 변경. 적용 가능한 기존 증거는 재사용한다.

## 구성과 진행

1. `music-core`: 공통 계약, legacy 순수 Kotlin 알고리즘 재사용, 확장 특징·근거, 결정적 구성안·요청.
2. `server`의 v2 음악 경계: 선택 미디어 검증·임시 보관·분석, owner별 입력·작업, 단계별 attempt·비용·복구·삭제.
3. Android 담당자용 계약/예시, 입력별 실제 지원 확인표, CLI 비교 산출물. 사이트는 열지 않는다.

legacy 요약 알고리즘은 빌드 시 기존 Android-free 소스에서 package만 옮겨 컴파일한다. Android 앱 코드를 복제·수정하거나 JS로 계산하지 않는다.
v1은 호환 경로로 보존하고 v2의 입력/feature/composition/prompt/모델 버전을 별도로 기록한다.

- 특징 추출·구성안·요청 구현 뒤 8개 통과: `.local/music-implementation/core-green.log`.
- 서버 첫 필터 실행에서 Gradle의 다중 프로젝트 테스트 선택 문제로 공통 모듈에 서버 테스트 필터가 적용됐다. `:test`로 서버 루트를 명시했다. 설정 실패와 제품 동작 실패를 구분한다.

## 최종 로컬 검증

- `final-verification.log`: 전체 공통/서버 검증 54개 통과, 파일 전용 Kotlin CLI의 10개 입력 비교 완료.
- 추가 개인정보 경계 검증 후 `final-server-verification-2.log`: 서버 **38개 통과**. 변경하지 않은 공통 모듈의 **18개 통과** 증거를 재사용한다. 합계 **56개, 실패/오류/건너뜀 0**.
- 실제 FFmpeg를 이용한 합성 음성 3종의 선택 구간 디코딩과 영상의 음성 제거 검사가 포함된다. 음악 생성/청취 검증이 아니다.
- 계정·역할 서명/nonce/소유권, PHONE 첫 생성/범위 변경 거절, 분석 전용 검토→캐시 재사용→음악, 실패 소재의 명시적 제외, 예산 원자성, 응답 유실/재시작/저장 응답 복구, 전송 중 취소/삭제, 기존 LIVE/READY 범위 참조와 frozen/원장 불변을 임시 DB/대역으로 검사했다.
- 실제 전송 어댑터가 테스트 permit을 **키 조회 전에 거절**하는 테스트가 있다. 실제 유료 호출 0.
- 사진은 내용 검사·메타데이터 제거·암호화·철회·재업로드·삭제 실패 대기 상태를 검증했다. 직접 음악 사진은 허용된 분석 소재 밖에서 새 가사 사실을 추출하지 않도록 요청한다. 이 지시의 실제 음악 AI 준수/청취는 미검증이다.
- 보존 SDK DB SHA256은 기존 provenance와 일치한다. 검토 시작 report에 기록된 차량 소스 **14개 해시 모두 일치**한다. 이번 구현에서 Android/UI/테마/자산을 추가 수정하지 않았다. 앞선 요약기 2파일 수정은 그대로 보존했다.
- 보호 문서의 diff 없음, `git diff --check` 통과. 원본 SDK/frozen/기존 음원/기존 비용 원장을 수정하는 실행은 하지 않았다.

증거는 `.local/music-implementation/verification.json`, `music-review-final.json`, 위 로그 및 `red-*` XML에 있다. 원본 보고서 `.local/logic-review/run-20261114-011013-matched/initial-report.json`은 읽기만 했다. 새 CLI는 기존 파일/입력을 덮어쓰는 출력 경로를 거절한다.

## 자체 검토에서 수정한 사항

1. 단조 시각/소스별 공백/부족한 관측을 전체 경로·시간으로 승격하지 않도록 기존 수정과 회귀를 보존했다. 중복/역순/FRESH 오표시, 요청 시각, 알려진 epoch 시작을 추가로 검사하고 진행 방향 평균을 원형 평균으로 수정했다.
2. 분석과 음악의 idempotency 종류를 구분하고, 새 intent로 동일 입력을 보내거나 접수 불명 분석을 다른 작업에서 다시 보내는 경우도 송신 fence로 막았다.
3. 무가사 장르 편성에서 보컬 레이어/화음을 제거하고, JSON 텍스트로 함께 반환된 가사·구조를 분리하면서 원래 텍스트를 보존했다.
4. 미디어 동의/삭제 경합을 결과 저장 전에 다시 확인하고, 파생본 해시를 frozen 입력에 묶었다. 정리 실패는 대기 상태로 보이며 원본 재업로드로 몰래 다른 파생본을 끼우지 못한다.
5. 새 미디어 원본/base64 요청 전문을 추적 파일/원장에 복제하지 않는다. 서버/제공자 정리 확인과 잔여 보관 가능성을 구분한다.

검증 과정에서 테스트 선택 설정, 호환 fixture의 JSON 괄호/READY 선행 상태, 사진 보호 문구의 잘못된 요청 경로를 수정했다. 이 실패를 제품 결함/실제 통합 성공과 혼동하지 않는다. 관련 로그를 보존했다.

## 완료 범위와 유예

승인된 **음악 핵심의 로컬 구현과 검증**을 완료했다. 새 계약/엔진/미디어 어댑터/구성안·요청/작업·복구·저장 경로와 앱 담당자용 예시가 있다. 제품 판단용 설명은 `music-core-review.md`, 인수 계약은 `music-core-handoff.md`다.

**실제 통합 확인 및 전체 제품 완료는 아니다.** Android 필드별 신규 SDK 수신·권한·수명, 실제 계정 로그인/Keystore/HTTPS, 외부 미디어 분석/음악 생성, 실제 가창/구성/청취, 차량 첫 클릭·폰 연결·앨범/동기화는 별도 승인/다른 담당자의 통합이 필요하다. 기존 검증 유예/한계를 유지한다. 과거 브라우저 검토 도구의 재빌드는 이번 새 파일 전용 CLI의 검증으로 대신했다고 주장하지 않는다.

추가 유료 호출·앱/Pleos/음악 서버/사이트 실행·자동 push/배포/업로드·Guard/훅/상주 에이전트/개인 메모리 저장은 하지 않았다.
