# 새 채팅용 구현 Goal 프롬프트

이 문서는 붙여넣기용 문안이다. 파일 작성·열람 자체로 구현·기기 시험·Goal/Guard 실행·유료 호출을 승인하지 않는다. 사용자가 새 채팅에 실행 지시로 전달할 때만 아래 범위를 적용한다.

```text
오늘의 트랙(Today’s Track)의 제출용 구현을 Goal로 등록하고 시작해줘.

프로젝트 경로:
C:\Users\xiui\Documents\Projects\TodaysTrack

목표와 마감:
2026년 11월 15일 23:59 KST까지 제출 범위 S1~S4를 완성한다.
실제 차량 SDK 기록 → 여정 요약 → 차량에서 시작한 실제 AI 음악 생성 → 저장 → 앱 재실행 후 재감상을 연결하고, 시연 영상·실행 가능한 release APK·소스·재현 안내를 포함한 제출 패키지를 완성한다.

이번 지시로 S1~S4의 구현·로컬 빌드·전용 에뮬레이터 검증·영상 제작·패키지 준비를 승인한다. 이전의 “아직 구현하지 마” 제한은 이 범위에서 해제한다. 유료 호출·충전·외부 게시/업로드·이메일 발송·클라우드 배포는 승인하지 않는다. 이 프롬프트는 새 채팅에 사용자가 실행 지시로 전달한 경우에만 착수 승인으로 적용한다.

먼저 AGENTS.md와 다음 문서를 읽어줘.
- docs/development/implementation-plan.md — 현재 제출용 계획
- docs/development/implementation-follow-up.md — 미루는 기능·검증
- docs/development/workflow-guard.md — 실행 방식과 Guard 정책
- docs/development/technical-validation.md — 최신 기술 검증 결과
- docs/design/README.md
- docs/design/recording-and-journeys.md
- docs/design/data-api-and-jobs.md
- docs/product/product-plan.md

현재 실행 계획은 네 묶음이다.
S1: 수집
S2: 생성 연결 — 외부 AI 전송 없는 대역 연결
S3: 저장·재생 — 대역 검증 뒤 별도 승인된 실제 AI 연결
S4: 영상·제출 준비

진행 원칙:
- 단계별 소요시간이나 하루에 한 묶음 같은 날짜 배정을 가정하지 않는다. 기존 문서나 이전 대화의 날짜별 목표·소요시간 추정은 실행 일정으로 적용하지 않는다. 개발 일정의 고정 조건은 위 제출 마감이다.
- 각 작업의 선행 조건이 충족되면 바로 진행한다. 묶음이 끝났다고 다음 날짜까지 기다리거나 계속할지 묻지 않는다.
- 승인 대기나 외부 의존성이 생기면 가능한 독립 작업을 이어간다. 제품 방향을 크게 바꾸는 선택이나 반드시 필요한 사용자 판단만 질문한다.
- 마감을 이유로 필수 검증을 생략하거나 미완료·대역 결과를 실제 완성으로 표시하지 않는다.
- 기획서 두 개와 설계 v0.2 원문은 유지한다. 제출용 7번 참고자료도 공란으로 유지한다.
- 이전 P0~P8 상세 계획은 후속 기술 분류다. 그 전체를 제출의 선행 조건으로 끌어오지 않는다. 미루는 기능과 검증은 후속 계획에 보존하고 삭제하거나 완료 처리하지 않는다.

실행 방식:
- 한 명이 inline으로 승인 범위를 이어서 구현하고 묶음 단위로 자체 검토한다.
- Workflow Guard는 기본 사용하지 않는다. Guard 준비·실검증을 제출의 선행 조건으로 만들지 않는다.
- 자동 에이전트 분업·상주 작업자·훅 설치·개인 메모리 저장을 하지 않는다.
- 필요한 활성 Superpowers/ECC 스킬만 사용한다.
- 작은 백그라운드 수집 실험부터 시작한다. 같은 실패가 두 번 반복되면 원인을 조사하거나 접근을 바꾸며 승인된 독립 작업은 계속한다.
- 실제 백그라운드가 미지원/미확정이면 그대로 기록한다. 화면 유지형 제한 시연 같은 큰 대안은 사용자에게 판단을 요청하고, 임의로 제품 요구를 낮추지 않는다.
- Windroid 개발 중단 상태는 유지한다.

기술·제품 제약:
- 기술 상태는 technical-validation.md의 최신 결과를 우선한다. 기획서/AGENTS의 오래된 미검증 문구나 deferred-design-notes의 가정을 최신 확정 결과로 취급하지 않는다.
- 기존 validation 코드는 검증 probe이지 완성 제품이 아니다.
- 실제 AI가 곡을 생성한다. 규칙 기반 음표 작곡으로 바꾸지 않는다.
- 새 기록의 첫 곡은 차량에서 시작한다. 폰의 기존 곡 재생성은 후속 제품 범위에 유지한다.
- 실제 SDK 위치·누적거리 관측과 공백을 보존한다. 구간 시간/거리 API가 항상 제공된다고 가정하지 않는다. 검증된 누적거리 차이와 같은 boot의 앱 단조 시각을 활용하며 오래된 위치·누락을 실제 관측으로 채우지 않는다.
- 여정 전체의 분위기와 이동·머묾·귀환 순서를 표현하며 운전자 감정을 측정했다고 주장하지 않는다.
- 사진·메모 없이도 생성 가능해야 한다. 하루/여행 선택과 최소 음악 설정을 기억하고 기본은 기록이 모였음을 알린 뒤 한 번 눌러 생성하는 흐름이다.
- 키 보호·최소 인증·중복 전송 방지·호출/비용 한도·접수 불명 시 자동 재송신 금지·기록 보존은 제출 버전부터 유지한다.
- 실제 SDK 입력, 합성 환경, 대역 음원, 실제 새 생성, 파일 검사, 청취 품질을 구분한다.

유료 API:
기존 승인은 모두 소진됐으며 현재 추가 허용량은 0이다.
먼저 대역으로 저장·재감상 경로를 검증한다. 실제 생성이 필요해지면 전송할 요약/구성안·제공자/모델·음악/가사별 최대 호출 수·예상 총액 상한·재시도 정책을 구체화한 뒤 별도 승인을 요청한다. 키를 출력하거나 채팅에 요청하지 않는다.
승인 대기 중에도 가능한 구현·대역 검증·영상 준비는 계속한다.

완료 판단:
실제 사용자 흐름, 새 입력과 새 생성곡의 연결, 저장·재실행/오프라인 재감상, 영상 재생, release APK 설치/실행, 제출 자료의 재현성과 비밀정보 제외를 증거로 확인한다.
대역이나 기존 곡만 연결했다면 실제 AI 통합은 미완료다. 자체 테스트 통과나 Guard 판정만으로 Goal을 완료 처리하지 않는다.
실제 결과·진행 상태·남은 한계는 기존 계획/검증 문서에 기록한다. 제출 패키지 준비와 실제 외부 접수 완료를 구분한다.

현재 상태와 첫 작업을 짧게 설명한 뒤, 계획을 다시 길게 작성하거나 재인터뷰하지 말고 S1부터 구현을 시작해줘.
```
