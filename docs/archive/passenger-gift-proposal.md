# 02 앱 프로젝트 소개 / 심사 자료

접수번호(운영사 기재):

**앱명 / 프로젝트명: 조수석 선물**

## 1. 앱 한 줄 소개

운전자가 준비한 음악과 메시지를 이동 시간과 장소에 맞춰 차량이 진행하여, 동승자에게 특별한 시간을 선물하는 Pleos Connect 앱입니다.

## 2. 기획 배경

생일이나 기념일의 식사·여행을 준비할 때, 목적지에 도착하기 전 함께 이동하는 시간도 특별한 경험이 될 수 있습니다. 그러나 운전자는 이동 중 콘텐츠를 직접 고르고 메시지를 재생하거나 다음 순서를 진행하기 어렵습니다. 조수석 선물은 가까운 사람을 위해 준비한 마음을 이동 과정에서도 자연스럽게 전달하고 싶은 고객에 주목합니다.

초기 타깃은 연인의 생일·기념일에 식사나 여행으로 이동하는 시간을 준비하는 Pleos Connect 차량 운전자입니다. 첫 사용 장면을 ‘상대방을 태우고 목적지로 이동하면서 준비한 마음을 전달하는 상황’으로 좁힙니다. 사용자가 출발 전에 환영 멘트, 함께 들을 음악, 추억 이야기와 마지막 메시지를 준비하면 차량이 실제 이동 상황에 맞춰 진행하도록 설계합니다.

핵심 가치는 “내 차에 탄 사람에게, 내가 준비한 시간을 선물한다”입니다. 개인적인 콘텐츠와 실제 이동 장소·시간을 연결하여 함께 탑승한 사람만이 경험하는 작은 프로그램을 제공합니다. 운전자는 준비한 경험을 전달하면서 운전에 집중하고, 동승자는 단순한 대기 시간을 넘어 자신을 위해 구성된 이동을 즐길 수 있습니다. 준비에 들이는 수고보다 경험의 가치가 큰지는 아직 검증 전인 가설이며, 제작 과정과 동승자의 반응을 함께 확인합니다.

## 3. 앱 주요 기능 및 차량 특화 요소

### 가. 동승자를 위한 드라이브 프로그램 제작

출발 전 스마트폰·PC의 웹 제작 화면에서 ‘누구를 위한 이동인지’, ‘어떤 날인지’, ‘전하고 싶은 말’을 입력합니다. 앱은 환영, 음악, 추억, 질문, 마지막 메시지로 구성된 기본 틀을 제공하고, 사용자가 문장을 수정하거나 직접 준비한 오디오를 추가할 수 있도록 합니다.

각 항목은 순서를 바꿀 수 있는 콘텐츠 카드로 표현합니다. 기본 프로그램은 환영·추억·마지막 편지만 작성해도 완성되도록 하고, 음악과 질문 카드는 선택적으로 추가합니다. 템플릿이 기본 문장과 순서를 제공하고, 사용자는 자신의 이야기만 넣은 뒤 전체를 미리 들어볼 수 있습니다. 완성한 프로그램은 연결 코드를 이용해 차량 앱에 불러옵니다.

스마트폰에서도 메시지 재생은 가능하지만, 본 앱은 개인 콘텐츠의 순서, 실제 장소 진입, 차량 내비게이션의 목적지 확인, 오디오 중단·재개를 한 진행 흐름으로 묶습니다. 운전자가 휴대폰에서 장소와 재생 시점을 계속 확인할 필요를 줄이는 것이 차량 앱의 차별화 가설입니다. 기존 기능을 넘어서는 가치는 실제 이용 비교를 통해 검증합니다.

### 나. 이동 시간·장소에 맞춘 콘텐츠 재생

| 콘텐츠 카드 | 이용 예시 | 재생 조건 예시 |
| --- | --- | --- |
| 환영 | 동승자의 이름과 특별한 날을 담은 인사 | 정차 상태에서 사용자가 프로그램 시작 |
| 음악과 소개 | 함께 들을 음악과 그 곡을 고른 이유 | 프로그램 시작 후 설정한 시간이 경과 |
| 추억 이야기 | 함께 방문했던 장소에 관한 메시지 | 지정한 장소 주변에 진입 |
| 질문·퀴즈 | 두 사람의 추억에 관한 질문 | 설정한 시간 또는 장소 조건 충족 |
| 마지막 선물 | 편지와 준비한 일정 공개 | 지정한 목적지 주변 진입 후 순서에 따라 재생하거나, 정차 후 직접 실행 |

장소·시간 조건이 충족되면 콘텐츠를 대기열에 넣고, 현재 재생 중인 항목이 끝난 뒤 순서에 맞춰 이어갑니다. 같은 장소를 반복 통과해도 콘텐츠가 중복 실행되지 않도록 합니다.

### 다. 변동하는 여정에 맞춘 진행

출발 전 차량 내비게이션의 목적지와 프로그램의 목적지를 확인해 서로 다른 장소를 기준으로 진행하는 일을 줄입니다. 첫 버전은 사용자가 입력한 예상 이동 시간과 콘텐츠의 재생 길이로 순서를 미리 확인합니다. 이 예상 시간은 실제 교통을 반영한 도착 예정 시간과 구분합니다. 재생 분량이 예상 이동 시간을 넘으면 선택 카드를 줄이거나 마지막 편지를 정차 후 여는 방식으로 조정하도록 안내합니다.

실제 주행에서는 지연이나 경로 변경이 발생할 수 있습니다. 장소 카드는 진입 시 실행 후보로 등록하되, 실제 재생 시점에도 그 장소의 유효 조건을 확인합니다. 재생 전에 해당 구역을 벗어나면 보류하여 지나간 장소를 현재 장소처럼 안내하지 않습니다. 도착 구역에 들어오면 아직 시작하지 않은 선택 카드보다 마지막 메시지를 우선하되, 재생 중인 개인 메시지를 갑자기 끊지 않습니다. 대기·보류 규칙은 기본값으로 제공하고 사용자가 세부 조건을 모두 설정할 필요를 줄입니다.

동승자는 원하지 않는 콘텐츠를 일시정지하거나 건너뛸 수 있고, 프로그램 전체를 종료할 수 있습니다. 첫 버전의 질문 카드는 함께 답을 말하며 즐기는 형태로 구현하고, 휴대폰을 통한 답변 수집은 향후 확장으로 분리합니다. 차량 재생 화면에는 앞으로 공개될 편지 내용이 미리 나타나지 않도록 합니다.

### 라. 차량 공간과 연결되는 선물 경험

차량의 실제 위치와 이동 시간에 따라 콘텐츠가 열리고, 차량 오디오로 함께 감상하도록 합니다. 출발 전에는 제작·미리보기를, 주행 중에는 자동 진행과 간단한 재생 제어를 중심으로 구성합니다. 내비게이션 안내와 전화 등 우선되는 소리가 나오면 콘텐츠 재생을 중단하거나 줄이고 이후 이어가도록 처리합니다.

기능이 지원되는 차량에서는 정차 중 환영·마지막 메시지와 앰비언트 조명 연출을 연결하는 기능을 선택적으로 검토합니다. 콘텐츠 재생의 핵심 기능은 조명 지원 여부에 의존하지 않습니다. 전기차 전용 기능을 요구하지 않으며 Pleos Connect 탑재 차량을 대상으로 합니다.

## 4. 주요 사용 시나리오

운전자가 연인의 생일을 맞아 식당까지 함께 이동하는 시간을 준비합니다. 출발 전에 웹 제작 화면에서 생일 템플릿을 고르고 상대방에게 전할 인사, 추억 장소의 메시지, 마지막 편지를 작성합니다. 필요한 경우 음악과 소개 카드를 추가합니다.

운전자는 ‘프로그램 시작 후 5분’에 음악 카드를, 두 사람이 처음 만났던 장소 주변에 추억 카드를 연결합니다. 식당 인근에서는 마지막 편지가 재생되도록 설정합니다. 예상 이동 시간 안에 콘텐츠가 들어가는지 확인하고 전체를 미리 들어봅니다.

차량에 탑승한 뒤 연결 코드로 프로그램을 불러옵니다. 차량 내비게이션의 목적지와 준비한 식당이 일치하는지 확인하고 정차 상태에서 시작합니다. 환영 멘트가 나온 뒤, 경과 시간과 지정 장소에 맞춰 준비한 콘텐츠가 이어집니다. 운전자는 다음 항목을 직접 찾거나 재생 순서를 관리할 필요 없이 운전에 집중합니다.

경로가 바뀌어 추억 장소를 지나지 않으면 해당 카드는 보류됩니다. 도착 장소 인근에서는 마지막 편지가 대기열에 들어가며, 프로그램을 마친 뒤 운전자가 준비한 메시지와 콘텐츠 목록을 디지털 카드로 남길 수 있습니다. 실제 방문한 장소와 실행된 콘텐츠는 별도로 기록합니다.

## 5. 개발 계획

### 가. 제작 화면과 차량 앱 구현

프로그램을 준비하는 반응형 웹 제작 화면, 프로그램과 콘텐츠를 전달하는 서버, Kotlin 기반 Pleos Connect 차량 앱으로 구성합니다. 출품용 기본 구현 범위는 ‘프로그램 제작 → 차량 연결 → 콘텐츠 불러오기 → 시간·장소 조건에 따른 재생 → 종료’입니다.

웹에서는 생일·기념일용 기본 틀과 카드 편집, 재생 조건 설정, 순서 미리보기를 구현합니다. 차량 앱은 프로그램 불러오기, 목적지 확인, 현재 재생 상태 표시, 일시정지·건너뛰기·종료를 제공합니다. 미래 카드의 메시지 본문은 노출하지 않습니다. 음악과 이미지 등 내려받을 수 있는 파일은 출발 전에 준비하며, SDK 음성 합성의 연결 의존성은 별도로 확인합니다.

### 나. SDK/API 활용 계획

| 도구 | 주요 사용 계획 |
| --- | --- |
| FusedLocation SDK | 차량 위치와 지정 영역 진입·이탈 알림을 이용한 장소 카드 실행 |
| NaviHelper SDK | 차량 내비게이션의 목적지 조회·확인과 프로그램 목적지 대조. 실제 반환 정보와 에뮬레이터 지원 여부를 초기 검증 |
| TextToSpeech SDK | 운전자가 작성한 환영 멘트·추억·편지의 음성 재생 |
| 앱 내부 시간 관리 | 사용자가 프로그램을 시작한 시점부터 경과 시간을 계산해 시간 카드 실행 |
| Android 미디어 기능 | 준비한 오디오 파일 재생, 오디오 포커스 처리, 중단·재개와 재생 순서 관리 |
| 서버·웹 제작 화면 | 프로그램 저장, 연결 코드 발급, 콘텐츠 전달과 수정 버전 관리 |
| Vehicle SDK — Light, 선택 확장 | 지원 여부를 확인한 뒤 정차 중 메시지와 앰비언트 조명 연출 연결 검토 |

첫 버전은 내비게이션 목적지 확인, 사용자가 지정한 장소와 프로그램 시작 후 경과 시간으로 동작하도록 구현합니다. NaviHelper의 목적지 조회를 사용할 수 없는 환경에서는 그 상태를 알리고 사용자가 프로그램 목적지를 확인하도록 합니다. 실제 도착 예정 시간에 따른 자동 분량 조정은 제공 필드·이벤트를 검증한 뒤 확장합니다. 기본 구현에서 교통 상황을 예측하거나 차량의 이동 시작을 자동 판별한다고 설명하지 않습니다.

### 다. 콘텐츠 처리와 재생 엔진

카드마다 콘텐츠 종류, 순서, 실행 조건, 중요도와 재생 상태를 저장합니다. 재생 상태를 ‘대기·조건 충족·재생 중·완료·보류’로 관리해 재진입이나 앱 재개 시 중복 재생을 방지합니다. 여러 조건이 동시에 충족되면 순서와 중요도에 따라 대기열을 정리합니다.

첫 구현에서는 사용자가 직접 작성한 문장과 준비한 샘플 음원을 사용합니다. 시연은 이용 범위가 확인된 음원으로 진행하고, 일반 이용자의 음원 가져오기·공유는 해당 콘텐츠의 이용 조건에 맞춰 설계합니다. 외부 스트리밍 서비스의 임의 재생 제어와 생성형 AI 대본 작성 기능은 기본 구현의 전제로 두지 않습니다. 음성 문장은 지정된 TextToSpeech SDK로 재생하며, Gleo Interface 승인이나 상시 음성 청취를 요구하지 않는 구조로 개발합니다.

개인 메시지와 장소 정보는 프로그램 이용에 필요한 범위에서 보관하고, 사용자가 프로그램과 기록을 삭제할 수 있도록 합니다. 동승자 이름이나 개인적인 메시지가 차량에 계속 노출되지 않도록 프로그램 종료와 연결 해제 흐름을 제공합니다.

### 라. 개발 순서와 검증

1. 프로그램·카드의 데이터 구조와 웹 제작·미리보기 화면을 구현합니다.
2. 차량 앱에서 연결 코드로 프로그램을 불러오고 음원·TTS 재생을 연결합니다.
3. 에뮬레이터에서 내비게이션 목적지 조회, 위치 수신과 지정 영역 진입·이탈 알림을 검증합니다.
4. 시간·장소 조건, 중복 진입, 경로 변경에 따른 카드 보류, 동시 조건 충족을 검증합니다.
5. 내비게이션 안내·전화에 따른 오디오 포커스 변경과 재생 재개, 다운로드 실패와 위치 누락 상황을 확인합니다.
6. 최종 시연은 생일 드라이브 한 편을 대상으로 제작부터 실제 조건에 따른 재생까지 보여주도록 구성합니다. 같은 프로그램에서 정상 경로와 장소를 지나치지 않는 경로를 비교해 진행 방식이 실제 이동에 따라 달라지는지 보여줍니다.
7. 사용자가 휴대폰에서 직접 재생하는 경우와 비교해 제작 부담, 운전자의 진행 조작, 전달 시점의 적절함과 동승자 만족도를 확인합니다. 조작 횟수와 만족도는 계획된 측정 항목이며 아직 검증 결과는 없습니다.

개발 범위의 기술적 근거는 [Pleos SDK 안내](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/), [FusedLocation SDK 문서](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/FusedLocation/intro), [NaviHelper SDK 문서](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/NaviHelper/intro)를 기준으로 확인합니다.

## 6. 기대효과 및 발전 가능성

### 가. 사용자에게 제공하는 가치

운전자는 출발 전에 준비한 마음을 이동 중에도 자연스럽게 전달할 수 있습니다. 동승자는 자신을 위해 구성된 음악과 이야기를 실제 장소·이동 시간과 함께 경험합니다. 앱이 콘텐츠 순서를 진행함으로써 운전자가 이동 중 재생과 진행을 관리하는 부담을 줄이는 것을 목표로 합니다.

개인 메시지가 실제 이동 상황과 연결된다는 점에서 차량 공간의 의미를 확장합니다. 같은 목적지로 가는 이동이라도 누가 준비하고 누구와 함께하는지에 따라 다른 경험이 되도록 합니다.

### 나. 타깃과 초기 사용자 확보

초기에는 연인의 생일·기념일 이동을 준비하는 차량 이용자에게 집중합니다. 사례형 템플릿과 체험 시연으로 첫 제작을 돕고, 기본 문장을 바꾸는 것만으로 프로그램을 완성할 수 있는지 확인합니다. 첫 실행 후 제작자가 다음 행사에 기존 프로그램을 복제·수정하거나, 선물을 받은 동승자가 새 제작자가 되는 흐름을 검증합니다. 복제 시 이전 대상의 개인 메시지와 장소는 검토·수정하도록 안내합니다.

이벤트 중심 서비스라는 점을 고려해 매일 사용을 전제로 하지 않습니다. 특별한 날의 재사용과 프로그램을 선물받은 사람의 신규 제작 전환을 함께 살펴봅니다.

### 다. 이용 지표와 검증 계획

출시 전 단계에서 확인되지 않은 사용자 수와 재방문율을 실적으로 제시하지 않습니다. 초기 운영에서는 다음 지표를 측정해 서비스의 가치를 검증합니다.

- **MAU:** 한 달 동안 프로그램을 제작·수정하거나 차량에서 실행한 고유 사용자 수. 제작과 실행 활동은 구분합니다.
- **제작 완료율:** 제작을 시작한 사용자 중 차량에서 실행 가능한 프로그램을 완성한 비율.
- **실행 전환율:** 제작 완료 프로그램 중 차량에 불러와 실제 실행한 비율.
- **경험 완료율:** 실행 프로그램 중 마지막 필수 콘텐츠까지 재생된 비율. 사용자 중단과 기술적 실패를 구분합니다.
- **재방문율:** 첫 제작 사용자 중 이후 90일 이내 다시 프로그램을 제작한 비율. 기념일 중심 이용 특성에 맞춰 장기 코호트도 살펴봅니다.
- **경험 만족도:** 제작 소요 시간, 개인적인 느낌, 동승자의 만족도와 다시 이용할 의향을 확인합니다.
- **차량 연동 기여:** 휴대폰 수동 재생과 비교해 운전자의 진행 조작과 전달 시점이 어떻게 달라지는지 확인합니다.
- **운영 효율:** 프로그램별 음성 합성·파일 저장·전달 비용과 기술적 실행 실패율을 측정합니다.

### 라. 발전 가능성

개인적인 생일·기념일 프로그램의 이용 가치를 검증한 뒤 부모님과의 추억 여행, 친구 환영, 가족 나들이 등으로 콘텐츠 틀을 확대합니다. 전문 창작자의 오디오 프로그램이나 관광 콘텐츠와 연결하는 방안도 검토할 수 있습니다.

수익모델은 특별한 날의 프로그램 단위 구매와 추가 템플릿 등을 우선 가설로 검토합니다. 이용 빈도가 낮을 수 있으므로 구독이 적합하다고 전제하지 않습니다. 제작 미리보기 이후의 결제 의향과 실행 완료 경험을 확인하고, 프로그램별 수입에서 음성 합성·저장·전달 변동비를 차감해 운영 가능성을 평가합니다. 가격과 예상 MAU·재방문율의 수치 예측은 초기 이용 자료를 확보한 뒤 산정합니다.
