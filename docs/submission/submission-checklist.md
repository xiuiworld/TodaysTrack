## 공식 안내와 대조

- 저장소의 소스와 `apk/` 폴더의 release APK를 제공한다. 사용자 지정 영문 팀명 MamboCore를 사용한 파일명은 `MamboCore_TodaysTrack_release.apk`다. Release에도 동일 파일을 제공한다.
- README에 앱 이름·소개, 실행 안내, 테스트 환경·설정, Pleos 버전·화면 규격, APK 경로·Release 링크를 명시한다.
- 접수 메일에는 저장소 주소와 **심사 기준으로 제출할 전체 커밋 해시**를 적는다. 제출 직전 최신 원격 main은 `git ls-remote origin refs/heads/main`으로 확인할 수 있다. APK 실행 코드의 고정 커밋은 위와 같이 별도로 안내한다.
- 공식 안내상 비공개 저장소도 접수할 수 있고 심사용 계정 초대는 요구하지 않는다. 11월 16일까지 공개로 전환하고 1차 결과 발표일인 11월 23일까지 공개 상태를 유지해야 한다. 이 작업은 사용자 승인에 따라 미리 공개 상태로 준비한다.
- 접수 기간은 공식 안내의 2026년 11월 15일까지다. 제출을 수정한다면 마감 전 마지막 자료가 심사 기준이며, 전체 자료·서명 동의서·팀원 CC를 다시 확인한다.

공개 저장소와 Release 준비는 **접수 메일을 보냈다는 뜻이 아니다**. 사용자 접수 여부를 임의로 완료 처리하지 않는다.

## 2026-11-15 접수 문서 검토와 메일 준비

- 사용자가 작성한 공식 양식의 PDF 8쪽을 이미지로 확인했다. 미작성이라고 설명한 부분을 제외하고 표 깨짐·글자 잘림·글꼴 깨짐은 보이지 않았다. 4쪽 하단 여백과 6번의 단일 문단은 공식 양식의 편집 제약을 고려해 유지하기로 했다.
- 6번 기대효과 및 발전 가능성은 현재 `docs/proposal.md` 본문과 공백을 제외하면 동일했다. 고객 확보·재사용 이유·지표 산정 계획·확장 방향이 누락되지 않았으며, 계획을 달성한 성과처럼 표현하지 않았다. 5쪽 마지막 소제목 앞 간격 정리는 선택 사항으로 안내했다.
- 마지막 페이지의 앱명 빈칸과 참가자 각자의 동의·본인 서명·실제 서명일은 사용자가 마무리할 항목이다. 팀원 CC는 개별 서명을 대신하지 않는다. 서명 이미지 삽입 또는 출력 후 서명·스캔은 문서 작성 방법으로 안내했으며, 특정 전자서명 방식의 운영사 승인을 확인한 것은 아니다.
- [공식 제출 안내](https://appdevchallenge.auto-hmg.io/guide/submission)와 FAQ에는 PDF 제출을 의무로 지정한 문구가 없었다. DOCX 공식 양식을 작성·서명해 이메일로 제출하도록 안내한다. PDF는 표·글꼴·페이지 배치를 보존하기 위한 추천 형식이며 별도 필수 요건으로 표현하지 않는다.
- 접수 메일 문안과 파일명은 [메일 초안](email-template.md)에 보존한다. 사용자는 작성한 메일에 최종 커밋 항목을 넣지 않았다고 설명했다. 공식 안내의 전체 커밋 기재 요구는 위 체크리스트에 그대로 보존하며, 메일 발송·접수 완료 여부는 확인하지 않았다.
- 공개 기록에는 연락처·실명·서명·실제 작성한 신청서 또는 원본 채팅을 복사하지 않는다. 작성된 DOCX·PDF와 검토용 추출 텍스트·페이지 이미지는 로컬에 보관한다. 저장소 기획서의 7번은 공란을 유지하고, 사용자가 제공한 영상·저장소·Release 링크는 실제 접수양식에서 사용한다.

## 기존 음원·영상 이용 조건 확인 기록

이전 로컬 준비 시 [Gemini API 약관](https://ai.google.dev/gemini-api/terms)과 [음악 생성 문서](https://ai.google.dev/gemini-api/docs/music-generation)를 확인했다. 당시 특정 아티스트 모방·제3자 가사·개인 경로·사진을 요청에 넣지 않았고 음원 원본을 보존했다. 이 기록은 현재의 독점권·저작권 성립이나 유사성·가창·청취 품질의 보증이 아니다. 새 이용 허락을 대신하지 않으며 [제3자 고지](../../THIRD_PARTY_NOTICES.md)를 함께 따른다.

이전 0.3 오프라인 검사에서 첫 클릭 보류 뒤 재클릭한 기록은 과거 검증에 보존한다. 최종 0.4의 단일 클릭 결과와 섞지 않는다. 기존 로컬 APK·영상·ZIP 보관본과 유료 예약·작업은 삭제하거나 다시 작성하지 않는다.
