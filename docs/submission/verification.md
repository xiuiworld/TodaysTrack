# 0.4 제출 검증과 한계

현재 기준은 **0.4.0-submission(5)**다. 아래는 기존에 확보한 실제 설치·기기 확인 결과이며, 공개 문서 정비에서 앱을 재실행하거나 유료 호출을 추가하지 않았다. 실행 코드·검증된 소스 ZIP은 `d7d99c4ed6ef6a8d8c24c605475ee6b3723e38aa`와 `submission-v0.4.0` 태그로 고정한다. main의 이후 기획서·심사용 문서 변경과 구분한다. 과거 0.3 판정은 [과거 기록](history/verification-0.3.md)에 보존한다.

## 공개 파일과 동일성

[GitHub Release](https://github.com/xiuiworld/TodaysTrack/releases/tag/submission-v0.4.0)의 APK·소스 ZIP과 SHA256 목록을 제공한다. [저장소 APK](../../apk/MamboCore_TodaysTrack_release.apk)는 같은 바이트에 공식 제출용 파일명을 붙였다. 원본 기기 XML·로그·DB·전체 증거 폴더는 로컬에 보존하며 GitHub 다운로드 자료로 안내하지 않는다.

| 파일 | SHA256 |
| --- | --- |
| MamboCore_TodaysTrack_release.apk | `1f5d75bb4d0c99e9847a7bacb5dd047e0ef36db72a35d6ca89c86e4dba25b47e` |
| TodaysTrack-source.zip | `58a2bf16e04c05be32ea1a3b7ba2e5d7f6a7fea4383cdc15cdd4b63fbaf67e95` |

APK의 기존 서명 지문은 `56fd311ccd45d0dd255a6241701175f7a530a668cb243d609c51962d310c0490`이다. 서명키는 공개하지 않는다.

소스 ZIP의 파일 286개를 inventory와 대조했고, 별도 추출 사본에서 서버·차량 release 빌드를 확인했다. 검증 APK와 추출 빌드 APK는 **전체 파일 해시가 다르지만 내부 ZIP 항목 198개의 내용은 모두 동일**하며 같은 서명 인증서를 확인했다. 전체 APK의 비트 단위 재현을 주장하지 않는다. 배포하는 파일은 기기 설치까지 확인한 위 원본 APK다.

## 이미 확보한 실제 증거

- 0.3(4)의 동일 UI/엔진 소스에서 실제 SDK 합성8km 기록→v2 음악 만들기→서버READY→차량AVAILABLE→보관함 재생을 확인했다. 실제 새 음악은101459ms와93335ms의2곡이며, 대역 MP3와 다르다. 별도 미디어 분석·유료 가사0이다.
- 영상의 새 곡은job33cfe9d5-accb-47e9-91e1-f2d1c2224324/MP3 SHA2561e9ab3fb6cee0489a3495c424c6be8720eaf509a7bb2f3ff93e353e50567d3a3/2247769bytes/93335ms다. 전체 디코딩·파일 해시 검사와 차량 저장을 확인했다. 실제 가창·음질·작곡 의도 준수는 청취 평가하지 않았다.
- 영상은1920×1080/24fps/H264+AAC/약148.04초이며 화면과 기기 재생 소리 직접 녹화다. 생성 대기만 단축하고 마지막 저장곡 재감상·원래 기록 연결은 별도 촬영했다. 소리를 MP3 후삽입하거나 UI를 합성하지 않았다. MP4 SHA2561402514f9c0eabba8e75677392da366800c7c06e80018b85840b86bfe01b6fc0, 전체 디코딩exit0/로컬Chrome실제재생/errornull이다.
- 초기 결과 저장 키 미설정은 송신 전 보류된 별도 작업으로 남아 있다. 예약을 임의로 환불하거나 작업ID/고정 입력을 재작성하지 않았다. 준비·촬영의 실제 음악 송신2회와 송신 전 보류 예약을 합쳐 이번USD0.30을 소진했다. 전역 보수적 예약USD0.70은 실제 청구액과 다르다.
- uiautomator가exit0으로 끝나면서 고정 XML을 갱신하지 않아 예전 화면을 읽은 관측 실패가 있었다. 실제 녹화/PNG와MediaSession에는 정상 진행이 보였다. 이후 관측은 고유 XML 경로와 실제 PNG를 사용한다. 관측 도구 실패를 앱 오류나 첫 재생 실패로 바꾸어 쓰지 않는다.

## 0.4 최종 기기 확인 결과

기존 패키지에 동일 서명 -r 업데이트를 수행했고 실제 설치 파일 해시와 빌드 APK가 일치했다. 업데이트 전후 기존 기록8개/곡6개와 기존 v2 곡1:33·1:41, 대역1:39를 확인했다. 최종 기기 확인용 SDK 합성8km 기록1개를 새로 시작/마감해 현재 기록9개/곡6개다. 원래 기록·곡·고정 입력·작업을 삭제하거나 재작성하지 않았다.

새 기록에서 음악 만들기 확인→입력/구성안 보존→생성 승인 대기를 확인했다. 소진된 유료 설정을 비활성화하고 음악 API 키를 읽지 않는 서버로 실행했다. 새 유료 음악 송신0, 기존 서버 jobs5/attempts5/v2 jobs3/attempts2/예약USD0.70은 불변이다. 동일 동작 소스0.3의 위 실제 송신→저장 증거를 재사용하며,0.4에서 신규 유료 곡을 다시 만든 것으로 표시하지 않는다.

**첫 클릭은 이번0.4 확인에서 보류가 재현되지 않았다.** Wi-Fi/mobile data를 끄고 default network none을 확인한 뒤 앱을 COLD 시작했다. 보관함의 기존 v2 새 곡을 한 번 눌러 NONE/0→PLAYING의준비0초→2756→5761→8768ms 진행을 관측했다. 추가 재생 클릭은0이며 실제 PNG의pause/0:12 표시와 이후PAUSED/약1분 위치를 함께 확인했다. 네트워크 설정을 원복했다. 초기0초 준비 순간을 실패로 판정하지 않았고, 모든 기기/조건의 영구 해결이라고 확대하지 않는다. 재생 로직은 수정하지 않았다.

차량release48개·서버44개·공통18개 총110개 검사 실패/오류/건너뜀0, release 빌드 성공, lint 오류0/기존 경고11이다. 처음 서버 디코더2개가 경로 미설정으로 skip된 뒤 실제 FFmpeg 경로를 지정해 서버/공통 검사를 마쳤다. 중간Gradle 필터가 공통 모듈에도 적용돼 테스트 없음으로 실패한 로그는 별도 보존했다. 브라우저 모델10개 통과, Astryx doctor fail0/warn1(기존 Windows shim)이다. 비UI 제품/엔진 파일65개는 f7672ac와 동일하고, MainActivity는 이전22개 처리 메서드 보존 검증 당시의 파일 SHA256과 일치한다.

## 유지하는 한계
