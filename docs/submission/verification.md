# 0.4 제출 검증과 한계

현재 기준은 **0.4.0-submission(5)**다. 최종 설치 바이트/서명·첫 재생 클릭·분리 소스 빌드 결과는 최종 확인 뒤 이 문서와 evidence/release-verification.json에 기록한다. 이 문단은 아직 수행하지 않은 검사를 통과했다는 뜻이 아니다. 과거0.3 판정은 history/verification-0.3.md에 보존한다.

## 이미 확보한 실제 증거

- 0.3(4)의 동일 UI/엔진 소스에서 실제 SDK 합성8km 기록→v2 음악 만들기→서버READY→차량AVAILABLE→보관함 재생을 확인했다. 실제 새 음악은101459ms와93335ms의2곡이며, 대역 MP3와 다르다. 별도 미디어 분석·유료 가사0이다.
- 영상의 새 곡은job33cfe9d5-accb-47e9-91e1-f2d1c2224324/MP3 SHA2561e9ab3fb6cee0489a3495c424c6be8720eaf509a7bb2f3ff93e353e50567d3a3/2247769bytes/93335ms다. 전체 디코딩·파일 해시 검사와 차량 저장을 확인했다. 실제 가창·음질·작곡 의도 준수는 청취 평가하지 않았다.
- 영상은1920×1080/24fps/H264+AAC/약148.04초이며 화면과 기기 재생 소리 직접 녹화다. 생성 대기만 단축하고 마지막 저장곡 재감상·원래 기록 연결은 별도 촬영했다. 소리를 MP3 후삽입하거나 UI를 합성하지 않았다. MP4 SHA2561402514f9c0eabba8e75677392da366800c7c06e80018b85840b86bfe01b6fc0, 전체 디코딩exit0/로컬Chrome실제재생/errornull이다.
- 초기 결과 저장 키 미설정은 송신 전 보류된 별도 작업으로 남아 있다. 예약을 임의로 환불하거나 작업ID/고정 입력을 재작성하지 않았다. 준비·촬영의 실제 음악 송신2회와 송신 전 보류 예약을 합쳐 이번USD0.30을 소진했다. 전역 보수적 예약USD0.70은 실제 청구액과 다르다.
- uiautomator가exit0으로 끝나면서 고정 XML을 갱신하지 않아 예전 화면을 읽은 관측 실패가 있었다. 실제 녹화/PNG와MediaSession에는 정상 진행이 보였다. 이후 관측은 고유 XML 경로와 실제 PNG를 사용한다. 관측 도구 실패를 앱 오류나 첫 재생 실패로 바꾸어 쓰지 않는다.

## 최종 버전에서 확인할 항목

앱·엔진 동작 소스와 버전 메타데이터 변경을 분리한다. 새 유료 음악을 다시 만들지 않는다. 동일 동작 소스의 위 실제 송신·저장 증거를 재사용하고,0.4 최종 APK에서는 설치/기존 데이터 보존·새 SDK 수집/마감·유료 실행 차단 상태·기존 v2 저장곡 조회/첫 재생/일시정지를 확인한다. 이 구분을0.4에서 새 유료 곡을 생성한 것처럼 표시하지 않는다.

첫 재생은 앱을 새로 실행하고 보관함 곡을 한 번 누른 뒤 실제 MediaSession의진행/일시정지와 고유 XML/PNG를 함께 기록한다. 단순0초 준비 순간, 관측 도구 실패, 실제로 진행되지 않은 첫 클릭을 구분한다. 재생 로직은 이번 UI 통합에서 수정하지 않는다.

## 유지하는 한계

청취 유예, 실차/장시간·일반 백그라운드, 폰/로그인/앨범·동기화의 후속 UI, 운영 서버·외부 배포/접수는 완료로 표시하지 않는다. 기존 고정 입력·작업·기록/곡과 기획/설계/7번·후속 계획을 보존한다. 공식 접수양식·개인정보·동의·서명은 사용자가 작성한다.
