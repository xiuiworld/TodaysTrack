# 02 앱 프로젝트 소개 / 심사 자료

접수번호(운영사 기재):

**앱명 / 프로젝트명: 오늘의 트랙 (Today's Track)**

## 1. 앱 한 줄 소개

주행이 끝난 뒤 차량에 기록된 여정으로 AI 음악을 만들어 함께 달린 시간을 한 곡으로 간직하는 Pleos Connect 앱입니다.

## 2. 기획 배경

친구나 연인과 다녀온 드라이브에는 목적지에서 보낸 시간뿐 아니라 함께 출발하고 달리고 돌아온 과정도 담겨 있습니다. 사진을 고르거나 영상을 편집하는 과정이 부담스러운 이용자에게는 이 여정을 간단히 기념할 방법이 필요합니다. 오늘의 트랙은 운전 중 별도 촬영이나 메모를 하지 않아도 이동 기록을 남기고 정차 후 그날을 소재로 한 곡을 만드는 경험을 제안합니다.

초기 고객은 음악을 즐기며 친구·연인과 주말 드라이브나 여행을 다니는 Pleos Connect 이용자입니다. 그 시간을 개인적인 콘텐츠로 남기고 싶은 이용자를 대상으로 합니다. 운전자는 기록과 생성을 시작하는 이용자이고 동승자는 같은 여정을 떠올리며 처음 듣는 공동 감상자입니다. 정차 후 생성을 요청하고 곡이 준비되면 그 자리에서 함께 듣거나 다음 차량 이용 때 감상하는 흐름으로 기획했습니다. 이후에도 같은 곡을 다시 재생하며 그날을 떠올리도록 합니다.

주행 후 생성은 출발부터 마무리까지의 기록을 보고 곡의 전개를 구성할 수 있다는 장점이 있습니다. 이용자가 여행을 긴 글로 다시 설명하거나 음악 생성 요청을 직접 작성할 필요 없이, 앱이 기록에서 반복·변화·이동 규모를 정리합니다. 장르와 가사 여부는 취향에 맞추고 선택 메모가 있으면 그날 남기고 싶은 이야기를 더합니다.

## 3. 앱 주요 기능 및 차량 특화 요소

### 가. 주행 전 기록부터 정차 후 첫 감상까지 차량에서 연결

출발 전 차량에서 기록을 시작하면 Pleos SDK의 위치와 지원되는 누적거리 정보를 수집합니다. 하루·여행 기록 기준과 음악 설정을 기억하고 주행 중에는 추가 촬영·입력·편집을 요구하지 않도록 구성합니다. 정차 후에는 여정 요약을 확인하고 음악 만들기를 실행합니다.

차량은 기록을 수집하는 장소이면서 동행자와 결과물을 처음 감상하는 공간입니다. 완성곡을 차량 스피커로 함께 듣고 그날의 제목을 붙여 보관하는 흐름으로, 이동이 끝난 직후의 경험을 소장으로 연결합니다. 준비·생성·편집은 정차 상태에서 제공하고 재생은 내비게이션 안내·전화와 오디오가 공존하도록 구성합니다. EV 전용으로 한정하지 않고 Pleos Connect와 필요한 정보의 지원 여부를 기준으로 합니다.

### 나. 위치와 차량 거리로 곡의 구성 재료 마련

위치 기록으로 관측 순서와 변화·반복을 정리하고 차량 누적거리의 유효한 증가량으로 확인된 이동 규모를 함께 해석합니다. 위치와 차량 거리는 서로 다른 기록 재료로 사용해 곡의 전개를 구성합니다. 지원 차량에서 이 정보를 직접 수집하고 별도 기록 도구 없이 기록·생성·감상을 이어가도록 하는 데 활용의 초점을 둡니다.

예를 들어 위치 변화가 이어지는 부분은 모티프를 발전시키는 전개로, 같은 위치가 반복 관측되는 부분은 악기를 덜거나 교환하는 대비로 요청할 수 있습니다. 시작과 끝의 관측 위치가 가까우면 앞의 테마를 변형해 떠올리는 마무리의 소재로 활용합니다. 관측 구간의 순서·비중과 누적거리로 확인한 이동 규모를 함께 정리해 일반적인 장르·분위기 요청에 여정별 구성 방향을 더합니다.

휴대폰 위치 기록으로도 유사한 기능 일부를 만들 수 있습니다. 본 기획은 차량 SDK의 위치·거리 정보를 직접 활용하고 기록 시작부터 정차 후 생성·공동 감상까지 차량 안에서 이어가는 편의에 가치를 둡니다. 차량 정보를 많이 나열하는 대신 어떤 기록이 곡의 반복·대비·회상 요청에 쓰였는지 이용자가 이해하도록 설명합니다.

데이터와 음악의 대응은 창작을 위한 해석입니다. 기록이 끊긴 부분은 임의로 채우지 않고 같은 좌표나 시작·끝의 근접성을 방문·귀가 사실로 단정하지 않습니다. 감정 측정이나 음표·초 단위의 일치를 약속하지 않으며 같은 기록과 설정으로 요청해도 생성 음원은 달라질 수 있습니다.

### 다. 음악 취향과 남기고 싶은 이야기를 함께 반영

가사 있는 노래와 무가사 연주곡, 장르는 사용자가 고릅니다. AI에는 여정 구성안과 음악 설정을 전달해 가사와 곡을 함께 생성하도록 요청합니다. 모든 가사를 도로·거리·목적지 이야기로 고정하지 않고 선택 메모를 더하는 확장에서는 이용자가 남긴 이야기를 가사 주제로 활용할 계획입니다. 메모가 없으면 창작 주제를 사용하되 확인하지 못한 장소·사람·사건을 실제 경험처럼 쓰지 않도록 합니다.

기본 개인화는 내 이동 기록을 곡의 구성 재료로 쓰고 완성곡을 해당 날짜·여정과 연결해 보관하는 데 있습니다. 선택 메모·사진을 더하는 확장에서는 이용자가 직접 남긴 이야기·장면까지 곡의 소재로 반영합니다.

사진·메모와 수동으로 고른 음성·영상·환경음·흥얼거림은 개인적인 소재를 더하는 선택 기능으로 확장합니다. 자동 녹음·촬영을 전제로 하지 않으며 재료를 추가하지 않아도 기록만으로 곡을 만드는 흐름을 유지합니다.

### 라. 저장곡의 재감상과 여행 단위 소장

완성곡은 날짜·여정 요약·제목·커버와 함께 보관합니다. 다음 드라이브나 여행을 떠올리고 싶은 날 보관함에서 찾아 듣고 재감상할 때는 새 음악을 생성하지 않고 저장된 음원을 재생합니다. 새 기록의 첫 곡은 차량에서 시작하고 기존 곡은 차량과 폰에서 감상·관리하는 방향입니다.

폰의 감상·보관·다운로드·공유·제목 및 커버 편집·기존 곡 재생성은 후속 확장입니다. 하루 곡은 월간 앨범으로, 여러 날의 여행은 날짜별 곡의 앨범이나 여행 전체를 담은 한 곡으로 남길 계획입니다. 기존 곡을 묶는 앨범 관리와 새 음악 생성은 구분합니다. 기록이 모였음을 알린 뒤 한 번 눌러 생성하는 흐름을 기본으로 삼고 자동 생성·원하는 기간 선택은 범위와 비용을 이해하고 선택하도록 제공합니다.

## 4. 주요 사용 시나리오

**친구와 다녀온 주말 드라이브를 한 곡으로 남기는 과정**

1. 출발 전 차량에서 기록을 시작합니다. 기억한 하루·여행 기준과 음악 설정을 사용하고 원할 때 장르와 가사 여부를 바꿉니다.
2. 카페와 전망대를 거쳐 돌아오는 동안 앱이 지원되는 주행 정보를 기록합니다. 이용자가 운전 중 장면을 촬영하거나 입력할 필요는 없습니다.
3. 주차 후 기록을 마치고 여정 요약과 누락 구간을 확인합니다. 기본 음악 설정으로 음악 만들기를 실행합니다.
4. 앱이 기록에서 곡의 전개를 정리하고 AI에 생성을 요청합니다. 생성 중에는 진행 상태를 확인하고 통신이 끊기면 원래 기록과 작업 상태를 보존해 이후 이어서 확인하도록 합니다.
5. 곡이 준비되면 차량에 저장합니다. 정차 중 완성되면 동행자와 함께 듣고 시간이 더 필요하면 다음 차량 이용 때 보관함에서 감상합니다. 예를 들어 ‘토요일 바다 드라이브’라는 제목으로 남겨 두고 이후에도 다시 듣습니다.

카페·전망대와 곡 제목은 이용 장면의 예시이며 장소·사건은 사용자가 제공하거나 방문이 확인된 정보만 활용합니다. 선택 메모와 사진을 더하는 확장에서는 ‘처음 같이 본 바다’ 같은 이야기를 남길 수 있습니다. 이후 폰에서 동행자에게 곡을 전달하고 여러 번의 드라이브를 월간 앨범으로 모으는 경험으로 넓힙니다.

## 5. 개발 계획

### 가. 핵심 경험을 먼저 연결하는 개발 범위

Kotlin 기반 차량용 Android 앱과 음악 생성 서버를 구성하고 Pleos Connect 에뮬레이터를 개발 환경으로 사용합니다. 우선 기록 시작 → SDK 데이터 수집 → 기록 마감 → 여정 특징·곡 구성안 작성 → AI 음악 생성 → 저장·감상의 흐름을 연결합니다. 정차 후 적은 조작으로 곡을 만들고 나중에 같은 음원을 다시 듣는 경험을 첫 개발 범위로 둡니다.

### 나. Pleos SDK와 AI의 역할

FusedLocation SDK는 위치와 수신 시각으로 관측 순서·위치 변화·반복을 정리하는 데 사용합니다. Vehicle SDK의 Odometer는 지원되는 누적거리로 이동 규모와 관측 구간의 비중을 해석하는 데 사용합니다. 필드별 지원·단위·누락을 확인하고 사용할 수 없는 값은 생성 재료에서 제외합니다. 트립 시간과 추가 차량 신호는 지원 여부에 따라 확장하며 와이퍼 상태를 날씨의 확정 사실로 해석하지 않습니다.

공통 Kotlin 모듈은 기록을 여정 특징·곡 구성안·음악 생성 요청으로 바꿉니다. 음악 생성은 Lyria 3.5를 연결해 가사와 곡을 함께 요청하는 방식으로 개발합니다. 선택 미디어 확장에서는 Gemini 3.8 Flash로 허용된 재료를 해석하고 음악 요청에 반영하는 역할을 나눕니다. 실제 작곡과 최종 음원 생성은 음악 AI가 담당합니다.

### 다. 기록 보호와 실패 대응

정밀 좌표는 차량에서 여정 특징으로 바꾸고 서버에는 생성에 필요한 요약을 전달합니다. 요청에 사용한 입력을 작업·음원과 연결해 기존 기록과 곡이 임의로 바뀌지 않도록 합니다. 비밀키는 서버에서 관리하고 기기와 곡의 소유권을 확인하는 구조를 둡니다. 선택 미디어는 사용자가 고른 파일·구간과 동의 범위를 따르고 보관·삭제·공유 범위를 구분합니다.

생성 중 통신이 끊기면 기록과 작업 상태를 보존하고 원래 요청의 상태를 확인하도록 합니다. 응답이 불명확한 요청을 자동으로 다시 보내 중복 비용이 발생하지 않도록 하고 생성 전에 허용한 요청 수와 비용 범위를 확인합니다. 생성에는 서버와 외부 통신을 사용하며 완성곡은 저장해 오프라인에서도 재감상하도록 구성합니다.

### 라. 개발 순서와 확장

먼저 차량의 기록·생성·저장·재생을 연결하고 차량 화면 제한과 오디오 공존을 반영합니다. 여정 특징과 생성 요청이 곡에 어떻게 반영되는지 살피며 음악의 전개와 감상 경험을 다듬습니다. 위치만 사용한 요청과 차량 정보를 더한 요청을 비교하는 방식으로 데이터 활용도 조정합니다.

그다음 계정·차량·폰 연결과 감상·보관을 확장하고 선택 재료·기존 곡 재생성·다운로드·공유를 연결합니다. 기록이 쌓이면 월간·여행 앨범과 기간 선택·자동 생성으로 발전시킵니다. 결과물의 공유 범위와 제공자 이용 조건, 생성 비용을 함께 고려해 서비스 범위를 정합니다.

## 6. 기대효과 및 발전 가능성

오늘의 트랙은 촬영·편집이나 긴 여행 설명 없이 자신의 주행 기록에서 출발한 곡을 만들고 날짜·여정과 연결해 간직하는 경험을 제안합니다. 주행이 끝난 뒤 전체 기록을 살펴 곡의 전개를 구성하고, Pleos SDK의 위치·지원 차량 정보와 차량 안의 기록·생성·공동 감상 흐름을 결합하는 데 차별화를 둡니다. 초기 고객은 음악을 즐기며 친구·연인과 주말 드라이브나 여행을 기념하고 싶은 Pleos Connect 이용자입니다. 드라이브·자동차 커뮤니티와 여행·음악 SNS에 사용 장면과 샘플곡을 소개하고, 관심을 보인 지원 차량 이용자의 첫 기록·생성·저장 체험으로 연결할 계획입니다. 추천 또는 이전 음악 설정을 사용하고 선택 재료 입력을 건너뛸 수 있게 해 첫 이용의 부담을 줄입니다. 재사용은 지난 여행의 곡을 다시 듣는 활동과 새 코스·동행자와의 여정을 새 곡으로 남기는 활동으로 나누어 설계합니다. 날짜·여정과 연결된 보관함으로 원하는 곡을 다시 찾고, 기억한 음악 설정으로 반복 입력을 줄입니다. 폰 공유를 연결한 뒤에는 동행자에게 곡과 여정 요약을 전달해 차량 밖에서도 사용 경험을 소개하되, 공유곡 감상자와 지원 차량에서 새 기록을 만드는 이용자는 구분합니다. 고객 확보는 소개 유입부터 지원 차량 이용자의 체험 시작, 첫 곡 생성·저장까지 나누어 살핍니다. MAU는 한 달 동안 기록·생성·감상 중 하나 이상을 이용한 고유 이용자로 정의하고 설치 차량 수와 사람 수를 구분하며, 예상 규모는 도달 가능한 지원 이용자 수와 첫 사용 전환율·월간 활동 비율의 근거를 확보한 뒤 산정합니다. Retention Rate는 첫 곡 생성 이용자의 30일 이내 새 생성·저장곡 재감상으로 살피고, 이용 단계별 이탈과 곡의 감상 품질·여정 연결감·소장 의향도 함께 확인할 계획입니다. 폰의 감상·편집·다운로드·공유와 선택 사진·메모·기존 곡 재생성을 연결하고, 하루 곡을 모은 월간 앨범과 날짜별 여행 앨범·여행 전체 한 곡으로 소장 경험을 넓힙니다. 앨범 재감상과 공유에서 첫 이용으로 이어지는 흐름도 살피며, 기존 곡을 묶거나 다시 듣는 데 새 생성을 요구하지 않습니다. 운영 가능성은 곡당 생성·재시도·보관·전달 비용과 생성 시간·실패율을 기준으로 살피고, 추가 스타일·재생성·고품질 내보내기 같은 유료 옵션은 변동비와 지불 의향을 고려해 검토합니다. 가격과 구독 모델을 미리 확정하지 않으며, 주행 중 반응형 음악은 선택 확장으로 두고 주행 후 한 곡을 만들어 간직하고 다시 듣는 경험에 집중합니다.
