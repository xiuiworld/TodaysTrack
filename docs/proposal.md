# 02 앱 프로젝트 소개 / 심사 자료

접수번호(운영사 기재):

**앱명 / 프로젝트명: 오늘의 트랙 (Today's Track)**

## 1. 앱 한 줄 소개

실제 주행 기록으로 여정이 끝난 뒤 AI가 그날의 분위기와 이동의 흐름을 담은 한 곡을 만들어, 함께 달린 시간을 음악으로 간직하는 Pleos Connect 앱입니다.

## 2. 기획 배경

친구·연인과 다녀온 드라이브에는 목적지의 풍경뿐 아니라 출발의 설렘, 중간에 들른 장소, 함께 돌아오는 시간도 포함됩니다. 오늘의 트랙은 이 이동 과정을 음악으로 남기고 싶지만 직접 작곡하거나 영상으로 편집하기는 부담스러운 이용자에게 주목합니다. 초기 타깃은 음악을 즐기며 동행자와의 드라이브·여행을 개인적인 콘텐츠로 소장하고 싶은 Pleos Connect 이용자입니다.

차량이 실제로 지나온 기록을 음악의 재료로 삼으면 별도의 촬영이나 긴 설명 없이도 자신의 여정을 담은 곡을 받을 수 있습니다. 작곡 기술을 배우지 않아도 이동 자체가 창작의 출발점이 되는 경험을 제안합니다. 동승자는 완성곡을 함께 듣고 같은 여정을 기억하는 공동 감상자가 됩니다.

오늘의 트랙은 **주행이 끝난 뒤 전체 여정을 보고 한 곡을 구성하는 점**에 집중합니다. 출발부터 경유·귀환까지의 흐름을 도입·전개·마무리에 담아, 이동 후에도 다시 듣고 간직할 결과물로 만듭니다. 고객이 실제로 소장하고 싶은 음악이 나오는지와 여정의 반영이 감상 가치를 더하는지는 초기 검증에서 확인합니다.

## 3. 앱 주요 기능 및 차량 특화 요소

### 가. 차량에서 실제 여정을 음악의 재료로 기록

출발 전 기록을 시작하면 차량 위치와 지원되는 거리·트립 시간 등을 수집합니다. 주행 중에는 추가 촬영·메모·편집을 요구하지 않습니다. 주행 후 기록을 이동 구간·확인된 사건·전체 비중으로 정리해 음악 생성에 사용합니다.

| 기록·입력 | 음악에 활용할 방향 |
| --- | --- |
| 이동 구간의 순서·상대적 비중 | 도입·중심 전개·마무리의 구성과 길이 비중 |
| 정리한 경로 변화 | 반복과 변화의 대비, 곡 전개의 특징 |
| 지원 차량 거리·트립 시간 | 위치와 함께 이동 규모·구간 비중을 해석해 전개에 반영 |
| 확인된 경유지 방문·귀환 | 음악적 전환과 처음의 분위기를 회고하는 마무리 |
| 출발 시간대·선택 장르 | 곡 전체의 음색·분위기 |
| 선택 사진·메모 | 남기고 싶은 장면·이야기를 가사와 앨범에 반영 |

차량 SDK를 부가정보 표시에 그치지 않고 곡의 구성안을 만드는 입력으로 활용합니다. 실제 수신값·앱 계산·사용자 입력을 구분하고, 지원되지 않는 정보는 반영했다고 표시하지 않습니다. 위치만 사용한 결과와 차량 정보까지 사용한 결과를 비교해 차량 데이터의 기여를 확인합니다.

### 나. 전체 여정의 분위기와 흐름을 담는 AI 음악 생성

기록을 마치면 앱이 전체 여정의 특징을 정리하고 곡의 구성안을 만듭니다. 음악 생성 AI가 구성안과 음악 설정을 바탕으로 멜로디·화성·보컬 또는 연주 및 최종 음원을 생성합니다. 일반적인 분위기 요청에 더해 실제 이동의 순서·비중·확인된 사건을 생성 요청에 반영합니다.

출발은 도입으로, 긴 이동은 중심 전개로, 확인된 귀환은 처음의 분위기를 떠올리는 마무리로 요청할 수 있습니다. 전체 색채와 여정의 전개를 함께 담되 특정 음표나 정확한 시점의 일치를 미리 보장하지 않습니다. 데이터 활용 내용과 실제 곡의 반영 결과를 구분해 검증합니다.

가사 있는 노래·무가사 연주곡과 장르는 선택할 수 있으며 추천 또는 이전 설정으로 바로 생성하도록 합니다. 사진·메모는 선택 사항으로 두어 기록만으로도 완성곡을 받을 수 있게 합니다. 가사에 포함하는 사실은 확인된 기록과 사용자가 제공한 내용에 근거하도록 하고 AI의 창작 표현과 구분합니다.

### 다. 이동 후에도 이어지는 소장과 재감상

완성곡은 제목·커버·날짜·여정 요약과 함께 보관합니다. 하루 곡들을 모아 월간 앨범으로, 여러 날의 여행 기록을 날짜별 곡의 앨범 또는 여행 전체 한 곡으로 남길 수 있습니다. 기존 곡을 묶는 동작과 새 음악 생성은 구분합니다.

첫 설정에서 하루·여행 기록 기준을 기억하고, 기본적으로 기록이 모였음을 알린 뒤 한 번 눌러 생성하도록 합니다. 자동 생성과 원하는 기간 선택 생성도 설정으로 제공하는 계획입니다. 반복 선택을 줄이면서 개인 취향과 기록 목적을 반영합니다.

차량에서 만든 곡은 폰에서도 감상·보관·다운로드·공유하고 제목·커버·앨범을 관리할 수 있도록 연계합니다. 기존 곡은 사진·메모나 가사 여부·장르를 바꿔 재생성할 수 있게 합니다. 새 기록의 첫 곡 생성은 차량에서 시작하고 폰은 이후 편집·소장 경험을 이어가는 역할로 계획합니다.

### 라. 차량 환경에서의 가치와 이용 원칙

차량에서 실제 기록을 수집하고, 주행 중 입력 부담 없이 이동한 뒤 정차 후 결과를 함께 감상하는 흐름을 제공합니다. 내비게이션 안내·전화와 오디오가 충돌하지 않도록 처리하고 편집은 정차 상태에서 제공하도록 합니다. EV 전용으로 한정하지 않고 Pleos Connect 및 필요한 정보의 지원 여부를 기준으로 합니다.

휴대폰 센서·위치 기록만으로도 유사한 기능 일부를 만들 수 있습니다. 본 앱은 실제 지원 차량 기록을 음악의 구성에 결합하고 차량에서 기록·첫 생성·감상을 이어가는 이점을 검증합니다. 차량에서만 생성하도록 제한하는 정책 자체를 모바일 대비 우위의 근거로 삼지 않습니다.

## 4. 주요 사용 시나리오

**친구와 다녀온 주말 드라이브를 한 곡으로 남기는 순간**

1. 운전자가 출발 전 기록을 시작합니다. 추천 또는 지난 음악 설정을 사용하고 원할 때 가사 여부·장르를 변경합니다.
2. 친구와 카페·전망대를 거쳐 돌아옵니다. 차량 앱은 지원 정보를 기록하며 운전 중 콘텐츠 제작을 요구하지 않습니다. 경유지 활용은 지정·방문이 확인된 정보에 한합니다.
3. 주차한 뒤 기록을 마치고 음악 만들기를 실행합니다. 원하면 사진이나 ‘처음 같이 본 바다’라는 한 줄 메모를 추가합니다.
4. 앱이 전체 기록에서 구성안을 만들고 AI가 곡을 생성합니다. 사용자는 실제로 다녀온 흐름을 소재로 만든 완성곡을 함께 듣고 저장합니다.
5. 이후 폰에서 다시 듣고 제목을 다듬거나 기존 기록과 곡을 바탕으로 다른 장르의 버전을 재생성합니다. 공유 범위를 선택해 동행자에게 전달합니다.

지속 이용 시 하루의 곡들을 모아 ‘나의 8월’ 같은 월간 앨범을 만들 수 있습니다. 4박 5일 여행에서는 기간의 실제 기록을 모아 여행 전체 한 곡 또는 날짜별 곡의 앨범으로 소장합니다. 이러한 방식은 핵심 주행 음악 경험을 축적하는 방향으로 제공합니다.

## 5. 개발 계획

### 가. 개발 범위와 구현 방향

Kotlin 기반 Android 앱을 Pleos Connect 에뮬레이터에서 개발·검증합니다. 핵심 구현은 **기록 시작 → 실제 데이터 수집 → 주행 종료 → 여정 요약·곡 구성안 → AI 음악 생성 → 저장·감상**입니다. 기간 설정·선택 입력·앨범과 폰의 편집·재생성·소장 기능을 연계하되 상세 화면·연결·데이터 구조는 후속 설계에서 정합니다. 현재는 기획 단계이며 실제 구현·생성 음원의 검증 전입니다.

### 나. Pleos SDK/API 사용 계획

| 도구 | 사용 계획과 핵심 경험의 연결 |
| --- | --- |
| FusedLocation SDK | 위치·시간 기반 이동 구간 정리, 지정 지점 진입·이탈로 실제 방문 확인 |
| Vehicle SDK — Odometer | 지원 거리·트립 시간을 위치와 함께 해석해 여정 규모·전개 비중의 생성 입력으로 사용 |
| Vehicle SDK — Wiper, 선택 확장 | 지원 확인 후 일부 음악 질감의 소재로 사용. 날씨 측정으로 해석하지 않음 |
| 앱의 기록 해석 | 노이즈·누락·출처를 확인하고 선택 기간의 곡 구성안과 음악 요청 작성 |
| 외부 AI 음악 생성 API | 가사·장르·곡 구성 요청으로 실제 음원 생성. 서비스·모델은 실험과 이용 조건 확인 후 선정 |
| 차량 미디어 및 폰 연계 | 오디오 포커스·저장된 곡 재생, 폰의 감상·편집·기존 곡 재생성·전달 |

API 존재와 실제 에뮬레이터 접근을 구분해 확인합니다. 차량값의 의미·단위·리셋·지원을 검증하고 수집하지 못한 값은 생성 요청에서 제외합니다. ADAS 카메라나 접근이 확인되지 않은 신호를 기본 전제로 두지 않습니다. [FusedLocation 문서](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/FusedLocation/intro), [Vehicle 문서](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/Vehicle/intro)

### 다. AI 생성과 기록 보호

전체 여정을 구간·전개·분위기로 표현하는 구성안을 만들고 음악 생성 API가 받을 수 있는 형식으로 변환합니다. 구간별 스타일·길이·가사를 지정하는 접근을 후보로 검토하되 실제 청취·비교로 요청 준수를 확인합니다. 같은 입력이 항상 같은 음악을 만든다는 전제는 두지 않습니다. [구조화 음악 생성의 기술 참고](https://elevenlabs.io/docs/eleven-api/guides/how-to/music/composition-plans)

원본 기록은 차량에 우선 보관하고 외부에는 생성에 필요한 요약 특징을 전달하는 방향으로 검토합니다. 사진·메모는 선택 입력으로 받고 외부 처리 범위를 구분합니다. 차량·폰 연결의 소유자 확인, 보관·삭제·공유 범위와 서비스 비밀키 관리는 후속 설계에서 구체화합니다.

AI 대기·실패·통신 중단 시 기록을 보존하고 생성 상태와 재시도를 제공합니다. 생성 실패를 다른 음원으로 대체해 사용자의 주행곡처럼 표시하지 않습니다. 완성곡은 저장해 재감상 시 재생성하지 않습니다. 통합 계약, 결과물 다운로드·공유 범위, 비용과 생성 시간은 서비스 선정 전에 확인합니다.

### 라. 개발·검증 순서

1. 샘플임을 표시한 대표 기록으로 AI 생성 실험을 수행하고 감상 품질과 구성 요청의 반영을 확인합니다.
2. 에뮬레이터에서 FusedLocation·Odometer의 실제 수신과 권한·단위·누락을 검증합니다. 샘플 실험을 SDK 연동 성공으로 간주하지 않습니다.
3. 같은 음악 설정에서 일반 생성 요청, 위치 기반 여정, 차량 정보를 결합한 여정을 비교합니다. 구성안과 실제 곡의 차이를 구분하고 반복 생성의 변동성도 고려해 차량 기록의 기여를 평가합니다.
4. 기록·생성·저장·감상을 연결한 뒤 기간 묶음·앨범·폰 연계를 검증합니다. 앱 중단·여러 날 기록·통신 실패·편집·재생성의 복구도 확인합니다.
5. 시연은 실제 수신 기록, 생성에 사용한 구성안, 실제 완성곡과 재감상을 보여줍니다. 구현·계획 범위와 시뮬레이션·SDK 수신값을 구분합니다.

## 6. 기대효과 및 발전 가능성

### 가. 고객 가치와 창의성

오늘의 트랙은 이동을 자신만의 음악이 만들어지는 창작 경험으로 확장합니다. 주행 중 음악 변화가 중심인 경험과 구별해, 완료된 전체 여정을 돌아보고 한 곡으로 소장하는 데 집중합니다. 동행자와 들으며 같은 날을 떠올리고 이후에도 재감상할 수 있습니다.

이동·풍경 음악화의 선행 사례는 존재합니다. 본 앱은 전체 여정의 AI 작곡, 지원 차량 정보의 활용, 결과물의 축적·소장이라는 조합을 실제 경험으로 검증합니다. 최초성이나 음질이 이미 입증됐다고 주장하지 않습니다.

### 나. 초기 고객 확보와 지속 이용

음악과 여행 기념물에 관심 있는 지원 차량 이용자에게 실제 샘플곡을 먼저 들려주고 자신의 첫 드라이브 기록과 감상으로 이어지는 흐름을 검증합니다. 동행자에게 전달된 곡은 차량 밖에서도 결과를 경험하는 접점이 됩니다. 공유 감상자와 지원 차량에서 새 기록을 만드는 이용자는 구분해 측정합니다.

다음 드라이브의 새 곡, 이전 여행의 재감상, 하루 곡의 월간 앨범과 여행 앨범을 지속 이용 가설로 둡니다. 매일 사용을 전제하지 않고 신규 생성과 기존 곡·앨범 감상을 나눠 봅니다. 설정 기억과 선택 사진·메모로 반복 사용의 제작 부담을 줄입니다.

### 다. 이용 지표와 사업 검증

확인된 이용자·배포 기반이 없어 예상 MAU와 Retention 수치를 임의로 제시하지 않습니다. 예상 MAU는 실제 도달 가능한 지원 이용자에 첫 경험 전환과 월간 활동 비율을 적용해 산정하고 초기 자료 확보 후 수치화합니다.

| 지표 | 측정 계획 |
| --- | --- |
| 핵심 경험 전환 | 기록 시작→생성 성공→첫 감상·저장의 이탈 구분 |
| MAU | 월간 기록·생성·감상의 고유 이용자. 차량 설치 수와 사람 수를 구분 |
| 재방문·Retention | 첫 곡 생성 코호트의 30일 이내 후속 활동. 새 생성·재감상과 차량·폰 이용을 구분 |
| 개인화 가치 | 일반 생성곡 대비 감상 품질·여정 연결감·소장 의향 |
| 앨범 가치 | 곡 모음 이후의 재감상·공유·다음 기록 |
| 운영 효율 | 곡당 AI·재시도·보관·전달 비용, 생성 시간·실패율 |

추가 스타일·재생성·고품질 내보내기 등의 유료 옵션은 지불 의향과 변동비를 확인한 뒤 검토합니다. 구독·가격을 미리 확정하지 않고 반복 생성과 장기 보관을 포함해 운영 가능성을 평가합니다.

### 라. 발전 방향

음악 품질과 재감상을 확인한 뒤 장르·곡 구성 제어와 앨범 경험을 고도화합니다. 차량에서 시작한 음악을 폰에서 다듬고 간직하는 연결을 발전시키되 실제 여정의 음악화를 중심으로 유지합니다. 주행 중 반응형 생성은 별도 확장으로 검토하며 첫 제품의 필수 조건으로 두지 않습니다.
