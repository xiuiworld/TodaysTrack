# 오늘의 트랙 · 설계 단계로 넘길 메모

작성일: 2026-11-12 · 상태: 설계 전 검토 자료

기존 내부 기획서에 섞여 있던 기술 검토를 분리한 메모다. **확정 설계·구현 계약·개발 착수 지시가 아니다.** 요구의 기준은 [내부 제품 기획서](../product/product-plan.md)이며 상세 설계는 이후 별도로 진행한다.

## 1. 다시 검토할 기존 가정

기존 0.1의 기본 악보 생성·로컬 렌더링, 동일 입력의 악보 재현, 음표·마디 기반 데이터 모델과 정밀 구간 대응은 규칙 기반 작곡을 전제로 했다. 현재는 기록 해석·구성안에서 **AI가 실제 곡을 생성**하므로 이 가정들을 구현 요구로 사용하지 않는다.

기존 내부 함수명, 생성 상태 목록, Composition·TrackAsset 등 스키마 초안은 확정 계약이 아니다. AI·폰 연계의 책임을 확인한 뒤 다시 결정한다. seed 고정, 5음 음계·32마디·80 BPM 같은 과거 제안값도 현재 요구가 아니다.

## 2. 유지할 설계 질문

| 분야 | 후속 설계에서 정할 것 |
| --- | --- |
| SDK | 실제 수신·샘플 출처 구분, 지원·권한·단위·실패 |
| 기간·수명주기 | 시동·프로세스 중단 뒤 복구, 하루 경계·시간대·여러 날 여행 묶음 |
| 품질 | 위치 노이즈·누락·오래된 값, Odometer 차분·리셋 |
| 해석 | 고정한 생성 입력·특징·구성안과 원본의 관계 |
| AI 작업 | 서비스·비동기 작업·보안·대기·실패·재시도·취소·중복·비용 |
| 결과 | 가사의 사실성·구성 준수·음량·파일 무결성·재생 가능성 |
| 저장·버전 | 입력·모델·설정·결과의 관계, 재생성 시 보존·교체 |
| 차량 재생 | 플랫폼 미디어·오디오 포커스·주행 제한·정차 편집 |
| 폰 | 플랫폼·소유자 확인·연결·동기화, 첫 생성 제한과 재생성의 구별 |
| 편집 | 제목·커버·순서는 재생성과 분리, 실제 가사·장르 변경은 새 음원 처리 |
| 사진·메모 | 전송·분석·보관 범위, 사진 추정과 사용자 사실 구분 |
| 앨범 | 곡과 모음의 관계·정렬, 미생성 기록과 완성곡 구별 |
| 삭제 | 원본·특징·요청·음원·커버·임시 파일·폰 사본의 삭제 범위 |
| 경합 | 생성 중 삭제, 폰·차량 동시 수정, 취소 뒤 결과 도착 |
| 진단 | 좌표·메모 노출 없이 오류·시간·지원 상태를 확인할 방법 |
| 운영 | 앱 통합 계약·결과물 이용권, 생성·재시도·보관·전달 원가 |

로컬 기록 보관과 모든 생성·폰 연계의 오프라인 제공은 다르다. 네트워크가 없을 때 기록 보존·생성 대기·완성곡 재생을 나눠 검토한다. AI 실패를 다른 음원으로 대체해 성공처럼 표시하지 않는다.

## 3. 설계 전 판단 자료

- 샘플임을 표시한 고정 여정의 AI 요청·실제 음원 비교.
- FusedLocation·Odometer의 실제 지원·수신·단위·누락·실행 수명주기.
- AI의 가사·구간 제어, 계약·원가·생성 시간·재시도 조건.
- 차량에서 폰까지 전달·재생·편집·기존 곡 재생성의 가능성.

이번 개정에서 이 검증을 실행하거나 설계를 완료한 것은 아니다. 엔드포인트·데이터베이스·서비스 배치·큐·동기화 프로토콜은 미정이다.
